# docs · 文档导航

> butler 文档按「规范 → 设计 → 决策 → 操作 → 计划」组织。本文件是导航，
> 规则在 `conventions/`、设计在 `specs/`、决策在 `adr/`，AI 进场路由在仓库根 `AGENTS.md`。

## 推荐阅读顺序（按架构与设计先后）

1. **进场**：本 `README.md` → `STATUS.md`（当前在哪、下一步做什么）→ `DESIGN-DECISIONS.md`（审美基线）
2. **规范（写代码前必读）**：`conventions/00`（变量入口）→ `01`（红线）→ `02`（命名文案）→ `03`（文件组织）→ `04`（提交信息）
3. **架构与设计**：`specs/architecture/`（A1-01 定位 → A1-02 一核多端 → A1-03 命名与语言 → A1-04 网页会话 → A1-05 总设计）→ `specs/domain/`（A2-01 总纲 → A2-02 Connector → A2-03 网页捕获 → A2-04..08 五业务域）→ `specs/cross-cutting/`（A4-01 L0）→ `specs/application/`（A3-01 信息架构）→ `specs/legacy/`（A0-01 旧系统，仅参照）
4. **决策记录**：`adr/`（ADR-001..016 / 018 / 022 / 026..032 / 034 / 007 等独立决策 + 模板，编号即时间/决策顺序；同主题多轮演进已合并归档——命名演进 = ADR-018、账户身份 = ADR-034、doubao 通道 = ADR-007）
5. **操作与计划**：`guides/01`（环境与命令）→ `plans/`（交付计划）

## 治理规则

- 单一事实来源；文档描述与实现不一致 → 先改文档再动代码
- 架构裁决 → `adr/ADR-编号-结论式标题.md`；审美裁决 → `DESIGN-DECISIONS.md`
- 一份新文档不知道放哪：是"必须遵守的约束" → `conventions/`；是"一次决策及理由" → `adr/`；
  其余按用途：怎么做 → `guides/`；长什么样 → `specs/`；什么时候做 → `plans/`

## 与标准结构的偏差（有意为之）

- `STATUS.md` 代替标准 `TODO.md`：进度卡已承担"要做"清单职能，避免双份事实来源
- `AGENTS.md` 在仓库根（而非 docs/）作为 AI 进场路由，仓库工具按根路径发现它
