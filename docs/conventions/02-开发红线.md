# 02 · 开发红线（❌ 禁止违反）

> **唯一源**：本主题以本文为准。
> 冲突时：本文 > 上级摘要 > 通用默认。

## 1. 总原则（❌ 禁止违反）

1. **严禁从旧仓库 auto-signin-kit 搬代码**（含改名式复制）。旧项目只是
   协议字典（→ PROTOCOL.md）+ 行为验收 oracle（同输入同结果）。
   判断口诀："这段代码是从旧仓库复制来的吗？" 是 → 打回。
2. **端零映射**：端上禁止 `if status in [...]` 式语义映射表；UI 只消费 core
   出产的 `kind` 谓词。判断口诀："这个业务规则改一下，要改几个文件？"
   超过 1 个（core 之外）→ 没归位。
3. **core 纯净**：`packages/core` 零框架依赖（FastAPI/Typer/SQLAlchemy 不得 import）。
4. **契约先行**：server 改 API → 重新生成 `packages/sdk`（openapi.sha256 必须同步）。
5. **显式报错不静默兜底**：配置非法/能力不支持 → 拒绝执行并如实上报，绝不静默降级
   （旧项目 dry_run 静默降级成真实执行的事故写进了 skill 教科书）。
6. **设计 token 唯一来源** `apps/web/src/styles/tokens.css`；审美决策写进
   `docs/design-decisions.md`，不许散落组件。
7. **每次实质提交后跑门禁**：`python scripts/verify_project.py --project . --test` 七项全绿。

## 2. 检查清单

- [ ] 没有任何代码来自旧仓库（含改名式复制）
- [ ] 业务规则改动只落在 `packages/core`（端零映射）
- [ ] core 未 import 任何框架
- [ ] 改过 API → `packages/sdk` 已重新生成且 openapi.sha256 同步
- [ ] 没有 try/except 吞错静默降级
- [ ] 样式只用 `tokens.css` 里的 token
- [ ] 门禁七项全绿
