# R4 网关独立进程 · 设计前置清单

> R4 = 网关独立进程（账户池/反代/规则引擎），路线图见 A1-03 §8 / A1-01 §5。
> 本清单是**立项任务书**：只汇编既有 spec 锚点、列设计裁决点与取证任务，
> 不写实现设计（先取证后实现，M2 先例）。产出回填：裁决点 → ADR；取证结论
> → 各连接器 PROTOCOL.md「§推理通道取证」小节；再落 A2 分册细案。
> 清单制定：2026-11-14（mac 侧会话）；R3 已收官（六连接器多 profile + 网页
> 通道 + 用量均闭环），R4 是下一个里程碑。

## 0. 执行纪律（红线级）

- **只读取证**：上游推理通道只读试探（看形状即止），领取/配置类写端点禁触
- **ToS 边界（A1-01 §6）**：L3 触碰 ToS 风险高——反代定位「个人多账户聚合，
  仅本机、仅本人账户」，不宣传不商用不共享；文档显式声明封号风险
- **不发未取证的头**；凭据/token 不落盘不进日志（样本先脱敏，A2-02 §8 口径）
- 拿不到 → 如实记 UNSUPPORTED，不猜（红线 5）；遇风控征兆立即停
- **Vault 审计是 R4 上线前的安全底线**（STATUS 既有裁决）：凭据池任何读取
  必须走 LayeredVault 同步审计路径，不得绕行

## 1. 既有锚点（汇编，实现必须落在这些约束内）

| 锚点 | 内容 |
|---|---|
| A1-01 §4 L3 | 组件链：Provider Adapter → Credential Pool → Router（余额/延迟/故障转移）→ Limiter → Meter → Audit；协议面 = OpenAI-compatible + Anthropic-compatible 两标准面；独立进程，主控管「配置与观测」、网关只管「转发与计数」 |
| A1-02 §1/§5 | apps/gateway 常驻 + 高并发独立进程；core 只有一份（纯 Python 零框架）；SQLite 单库（WAL），usage_samples 时序表按天分区 |
| A2-01 §2 | Action kind 已含 `gateway.route`（只读配置动作）；Run/Result/幂等键口径照旧 |
| A2-02 §3 | 三级扩展之三 = gateway provider 插件；**禁止声明式**；只做转发与计量（不做领取/签到编排） |
| A2-06 usage | UsageSample.source 已含 `gateway` 值——计量入账走既有 usage 通道 |
| STATUS 决策 | Vault 审计同步落账（事件总线只承载通知）；文件长度 600 行门禁适用于新进程代码 |

## 2. 设计裁决点（立项会话列出，逐条出 ADR 后才动代码）

- [ ] **进程边界**：gateway 是否 import butler_core 进程内直调（CLI/server 先例）
      还是走 server 契约 API（desktop/web 先例）？——凭据池需要 vault，
      转发热路径低延迟，两者张力待裁
- [ ] **主控通信形态**：A1-01 写「IPC/HTTP」二选一未定——配置下发/观测上报走哪条
- [ ] **凭据池形态**：现用现取（workbuddy ADR-008 同款）vs 池内驻留 TTL；
      凭据最小授权（A2-02 §5）在多 provider 并发下的口径
- [ ] **协议面鉴权**：本地 OpenAI/Anthropic 兼容端点的 API key 形态
      （127.0.0.1 单用户，A1-02「默认不设 JWT」口径如何落）
- [ ] **Router 最小集**：余额/延迟/故障转移三项 M1 全做还是只做其一；
      余额输入 = R2 额度快照（A2-06）的衔接点
- [ ] **规则引擎范围**：A1-01 称「规则引擎」，最小集是什么（路由规则表达）
- [ ] **Meter 口径**：逐调用 tokens 实测四家双通道 UNSUPPORTED（plans/01 §6）——
      网关侧计量 = 网关自己看得到的请求/响应计量，与 R2 聚合用量两账并存
- [ ] **技术栈**：Python 起步（将来 Go/Rust 只换此进程，A1-01）；框架选型随进程边界裁决

## 3. 取证清单（主线：各连接器的推理/对话通道形状）

> M1/M2 只打通了签到与用量；**反代的上游 = 各家的推理通道，目前零取证**。
> 与 M2 同构的逐家三问：

1. **推理通道形状**：各家有无推理/对话 API（或仅界面通道）？端点/鉴权
   （能否复用 M1 凭据链）/请求体/流式形状
2. **并发与风控边界**：账户级并发限制、限流特征、封号风险信号（只读试探）
3. **额度扣减语义**：推理调用如何扣 credits/额度（与 R2 余额快照衔接 → Router 输入）

- [ ] trae_cn：Cloud-IDE 会话有无模型代理 API（credits 扣减证据）
- [ ] qoder_cn：Cosy 会话的模型调用通道（credits 扣减证据）
- [ ] doubao_cn：CDP 界面通道已打通（ADR-007）——推理转发走 CDP 可行性
      与流式形状（若不可行，如实 UNSUPPORTED）
- [ ] workbuddy_cn：$wbEncrypted 会话的模型调用通道（85 包账本扣减证据）
- [ ] （范围裁决输入）web 两家（chatgpt/claude）：无 API key 通道是否纳入
      反代范围，还是反代首版只做四家桌面连接器

## 4. 阶段拆解建议（裁决 + 取证回收后细案）

| 阶段 | 内容 | 出口 |
|---|---|---|
| G0 | 本清单裁决点逐条出 ADR + 取证 spike 回收 | ADR 集 + PROTOCOL 推理通道小节 |
| G1 | apps/gateway 进程骨架 + 主控通信 + 契约（若走 OpenAPI） | 进程可启停、健康可观测 |
| G2 | Credential Pool（vault 审计路径复用） | 池取凭据全审计 |
| G3 | Router + Limiter 最小集 | 按裁决范围可路由 |
| G4 | Meter + Audit（usage_samples gateway 源入账） | 转发必有计量 |
| G5 | 两个协议面（OpenAI/Anthropic compatible） | 端到端转发验证 |
| G6 | 契约再生成 + 门禁九项 + 文档收口 | verify 全绿 |

## 5. 明确不在 R4 范围（防蔓延）

- 会话迁移（R5）；成本顾问/套餐对比（L6）；共享账户/转售（合规红线）
- 连接器新增家数（广度扩张不与 R4 混批）
- 领取类扩展（doubao 任务清扫 / workbuddy 成长中心——另立小批次，M2 既有裁决）
