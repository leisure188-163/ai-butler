# R5 会话迁移 · 设计前置清单

> R5 = 会话三级迁移（A1-03 §8 里程碑表；A1-01 §3 L4「产品上必须克制」）。
> 本清单是**立项任务书**：只汇编既有 spec 锚点、列设计裁决点与取证任务，
> 不写实现设计（R4 先例：裁决 → ADR，取证 → PROTOCOL 分册，再落 A2 细案）。
> 清单制定：2026-11-15（mac 侧会话）。

## 0. 执行纪律（红线级）

- **只读取证**：会话存储只读试探（看形状即止），写动作禁触；导出/导入端点
  只做官方明示能力的最小验证
- **ToS 边界（A1-01 §6）**：L4 触碰 ToS 风险高——只承诺「可迁移 + 可回退」，
  **不承诺「无缝」**；产品文案显式标注风控与封号风险；不做对抗性绕过
- **可回退是硬承诺**：任何迁移动作前必须先留快照；还原不依赖上游配合
- 遇风控征兆立即停（沿用 plans/02 §0 口径）；凭据/会话明文不落盘不进日志

## 1. 既有锚点（汇编，实现必须落在这些约束内）

| 锚点 | 内容 |
|---|---|
| A1-01 §3 L4 | 三级能力如实标注：`local`（本地会话文件迁移）/ `inject`（摘要注入新会话）/ `server`（官方共享能力）；产品上必须克制 |
| A2-04 §2 | `Session` 实体已定义（account_id / location / level: local\|inject\|server）——**零装配，R5 从零开** |
| A2-04 §3 | `SessionSourcePort`（本机会话/凭据扫描数据面）已立端口未实现 |
| A1-04 §6 | 网页两家（chatgpt/claude）**首批不做会话迁移**（对话代理也在 R4 后） |
| A2-01 §2 | Action kind 新增需走 ADR（如 `session.migrate`）；Run/Result/幂等口径照旧 |
| A0-01 | 旧系统无会话迁移知识——**R5 无 legacy oracle**，全部靠自家取证 |
| STATUS 遗留 | doubao「发消息属写动作」——会话注入/导出大概率也是写动作，取证与验证需用户逐次授权 |

## 2. 概念裁决点（~~待列~~ **先裁概念，再裁实现**）

### 裁决 A：「会话」指什么（最关键，先裁这个）

L4 的「会话」≠ 登录态（登录态 = 凭据，M1 已做迁移/多账户）。候选语义：

| 候选 | 内容 | local 级可行性 |
|---|---|---|
| A1 对话历史 | 各家客户端本地落的聊天记录/工作区上下文文件 | 看各家存储形状取证 |
| A2 工作区/配置上下文 | IDE 工作区设置、规则文件、prompt 预置（trae/qoder 类） | 大概率纯文件拷贝 |
| A3 两者皆是 | 按 kind 分：`conversation` / `workspace` 分开迁移 | 实体层 kind 字段 |

**建议**：A3（kind 分列），且首批只做 **A2 工作区/配置上下文**（纯文件、
低风控、可回退容易），A1 对话历史逐家取证后再开（写风险高）。

### 裁决 B：首批家数与通道

- 桌面四家（trae/qoder/doubao/workbuddy）本机文件可触及；网页两家已排除（A1-04）
- **建议**：trae_cn 先行（声明式 HTTP 家、存储形状 M1 已摸过 storage.json）、
  qoder_cn 次之；doubao/workbuddy 视取证（doubao 是 CDP 通道 + 写动作需授权）

### 裁决 C：inject 摘要注入的执行者

- core 只管编排与落账；摘要从哪来？候选：用户手动提供文本 / 接 LLM API /
  不做自动摘要（inject = 把结构化上下文模板写进新会话首条消息）
- **建议**：首批不做自动摘要（无 LLM 依赖、不发明），inject = 模板化上下文
  注入 + 用户确认后发送（发送 = 写动作，逐次授权）

### 裁决 D：server 级边界

- 只包装**官方明示的共享/同步能力**（如官方导出、官方跨设备同步开关），
  不逆向私有接口——超出即不做（YAGNI + 合规）

### 裁决 E：kind 与编排归属

- 新 Action kind `session.migrate`（走 ADR 立项）；编排 = execution 域用例
  （幂等键语义待定：会话迁移天然可重复？快照还原幂等口径）
- 新域还是挂 accounts？Session 实体在 accounts 域，迁移用例建议挂
  **accounts 域**（数据近）或 execution（编排近）——二选一

### 裁决 F：回退机制形态

- 快照存哪（数据根 `session-snapshots/<account_id>/` ？）、保留几代、
  还原入口（CLI `session restore` / server 契约 / web 按钮）

## 3. 取证清单（只读，逐家三问）

1. **会话存储形状**：各家客户端本地落什么会话文件（路径/格式/是否加密）、
   官方有无导出/同步端点
2. **写入边界**：还原/注入是否必须走写动作（客户端文件替换 / UI 自动化 /
   官方 API）；风控征兆有哪些
3. **可回退性**：替换前快照能否完整还原（文件级 vs 服务端状态）

- [ ] trae_cn：storage.json 及工作区上下文形状（M1 凭据链已摸过同文件，增量取证）
- [ ] qoder_cn：会话/工作区文件形状（M1 同域已知 auth.v1.dat，会话另找）
- [ ] doubao_cn：CDP 通道读写边界（写动作需用户授权，PROTOCOL §9 同款）
- [ ] workbuddy_cn：BYO-key 客户端的会话概念（可能只有 credits，无本地会话）

## 4. 阶段拆解建议（裁决 + 取证回收后细案）

| 阶段 | 内容 | 出口 |
|---|---|---|
| S0 | 本清单裁决点逐条出 ADR + 只读取证 spike 回收 | ADR 集 + 各家 PROTOCOL 会话小节 |
| S1 | Session 实体装配（SessionSourcePort 实现：dock 时枚举会话位置如实入库） | 「应用 → 账户」可见会话清单 |
| S2 | local 级迁移（首批 = 工作区/配置上下文）+ 快照/回退 | 端到端迁移 + 还原验证 |
| S3 | inject 模板注入（用户确认后发送，逐次授权） | 注入链路可演示 |
| S4 | server 级（官方能力包装）+ 契约/web 出口 | verify 全绿 + 文档收口 |

## 5. 明确不在 R5 范围（防蔓延）

- 无缝迁移承诺（违反 A1-01 L4 克制原则）
- 自动摘要生成（裁决 C 建议首批不做）
- 对话代理 / 聊天机器人化（R4 后另行立项）
- 网页两家会话迁移（A1-04 已排除首批）
- 跨机器同步（L7 生态层，另行立项）
