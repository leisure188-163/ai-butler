## D2 · 主题定位

- **纸墨（Cardstock & Ink）v6 · 中性工作台基底 + 数字锚点**（2026-11-14 用户裁决，
  修订 v5）：**「信息是主角」核心不变——无渐变、无彩色装饰、无 SaaS 卡片墙**；
  但 v5 用力过猛把正当的视觉锚点一并砍掉（真机对比旧系统判「low」），v6 补回
  三层锚点：
  1. **仪表盘速览四行 → KPI 数字卡**（4 列 grid，≤1280 折 2 列）：主数字
     `--text-3xl` tabular 大字 + 语义色点睛（健康正常绿/留意橙），副行安静；
     流量/日志为文本卡（`--text-xl`）——数字是锚点，标签不上彩
  2. **侧栏功能图标**：六项线性 SVG 16px（stroke=currentColor 随文字色），
     功能性锚点非装饰；品牌加墨青方徽「B」
  3. **容器边界感**：`.sheet` 升 `--radius-md` + `--shadow-soft`（新 token，
     每主题独立值）——轻阴影非重投影
- v5 以下形态维持退役：真比例卡面、金箔芯片、压印卡号、墨印章、卡扇动画、
  结果「印章」（仍为结果徽 .tag）
- **token 值**（唯一来源 `apps/web/src/styles/tokens.css`，红线 6）：
  - 案面 `#F1F3F4` / 纸白 `#FFFFFF` / 凹槽 `#E8EBED` / 纸绳线 `#D9DEE1`
  - 墨青 `#182831`（主文本与主按钮）/ 雾墨 `#54646D` / 弱化 `#84939B`（仅装饰）
  - 文本级强调 `#8A5D14`（白底 ≈4.9:1，激活态唯一彩）；
    金箔渐变 `--chip-gold-*` 退役
  - 语义五色分两档（分类词表由 core 出产，UI 只消费五词）：
    填充 base 档 + 正文 ink 档（白底全部 ≥4.5:1）
  - **应用小徽**：身份色六值 `--card-face-1..6` 单值保留（白字对比 ≥6:1 的渐变对
    退役），按应用 id 稳定散列分派；**身份色只允许出现在 AppBadge 单值点**
  - v6 新增：`--text-3xl: 32px`（KPI 主数字）、`--shadow-soft`（容器轻阴影，
    三主题各自定值；`--shadow-card` 留浮层）
- **结构（六页 IA，ADR-010）**：仪表盘 = 一句话结论 + TodoRail 三节 + KPI 速览卡（v6）；
  应用 = 六列表册 + 虚线邀请行；账户 = 9 列矩阵（MatrixTable，待办栏已迁出）；
  流量 = 每账户一块（小徽头行 + 活跃包/历史耗尽折叠/汇总原话/流水）；
  日志 = 结果徽 + 中性表头；列表仍是「行 + 发丝线」
- **多主题（v5）**：三套并列可切换——**纸墨**（浅·默认，基底值即上列）/
  **墨夜**（深：墨青夜底 `#10181E` + 纸白 `#E8EDF0`，金与语义五色整体提亮一档）/
  **暖纸**（浅护眼：米黄纸底 `#F4ECDD` + 暖墨 `#3A3226`，语义五色向暖压深半档）。
  默认**跟随系统**（`prefers-color-scheme` 实时跟随）。
  实现纪律：覆盖块只覆写颜色类令牌（含 `--color-on-ink`/`--color-ink-strong`
  随主题翻转），字体尺寸动效继承不复制；小徽身份色跨主题一致；
  切换 = `<html data-theme>`，设置存 `butler.settings.v1`（缺省 = 跟随系统）
- **字体/动静**：沿用 D4 纪律（系统栈、数字 `tabular-nums`、标识符 mono）；
  动效仅按压反馈（scale 0.97/110ms），卡扇揭示动效退役，
  全局尊重 `prefers-reduced-motion`；无 ALL-CAPS 眉标/箭头按钮/渐变装饰
- **v7 · 暖纸改绿纸感 + KPI 图标片（2026-11-16 用户裁决，参考清新工作台风）**：
  1. **暖纸主题重定调**：米黄暖纸 → **清新绿纸**——浅绿纸底 `#EAF2E6` +
     白卡 `#FFFFFF` + 墨绿 `#1D3326`（主文本/主按钮）+ 叶绿 `#2F7D4E`
     （文本级强调，白卡 ≈4.6:1）；主题名「暖纸」不变（词表规范词），
     仅 token 值更新（tokens.css warm 块，阴影转绿调）
  2. **「无彩色装饰」纪律放宽一档**：KPI 卡允许**彩色功能图标片**
     （30px 圆角片，底 = 语义五色 weak 档 / `--accent-weak`，描边图标）——
     色只表**功能分类**（健康=ok / 动作=accent / 流量=quiet / 班次=notice），
     **不表状态**；signal 状态染色纪律不变（数字语义色与结果徽仍只认五词，
     红线 2 不动摇）；仍禁渐变与卡片墙
  3. **KPI 占比环**：健康（healthy/total）与今日动作（done/total）卡加
     36px SVG 进度环——环只画**真实比值**，无数据（total=0）如实不画；
     健康环色随 unwell 谓词（有留意者转 attention），动作环恒 accent

- **浅色主题重定调 v8 · 晨雾（Mist）**（2026-11-18 用户裁决，参考现代 SaaS 工作台

## D3 · 布局与 IA

- **左侧边栏导航 · 六页平铺（2026-11-14 裁决，[ADR-010](adr/06-前端/ADR-010-六页平铺与外链交系统浏览器.md)）**：
  **仪表盘（默认）/ 应用 / 账户 / 流量 / 日志 / 设置**；顶栏单行「AI 智能助手管家」
  + 拉丁标 Butler，≤900px 顶条同样显示主名
- **侧栏视觉分组（v6.1，2026-11-15 用户裁决）**：三层组——**总览**（仪表盘）/
  **运营**（应用/账户/流量/日志）/ **系统**（设置）；纯视觉层，hash 直链与
  页面结构不变；新页（网关/迁移等）挂对应组即可扩展，≤900px 顶条保持平铺
  不显示组标
- 职责重排：待办栏三节归仪表盘，导入与「一键导入（n）」归应用页，
  领取/体检留账户页；规范 hash `#/dashboard / #/apps / #/accounts / #/traffic /
  #/logs / #/settings`，重定向表 v2（7 条）见 A3-01 v2 §3
- 提醒角标挂「仪表盘」项（待处理 + 非正常账户 + 临期凭据，条目数不去重）
- 页面状态走 **hash 直链**：可直链、可后退（ui-ux-pro-max 深链规则）
- 结论先行：仪表盘首屏只回答「今天有事要做吗？」——大字结论 + 速览四行 + 待办栏，
  不是横幅盒子
- **仪表盘图形化（v6.2，2026-11-15 用户裁决）**：取「资产状态型仪表盘」范式
  （1Password Watchtower 类），不用折线/饼图等监控图表库，全部内联 SVG/CSS 零依赖。
  三件套——① **近 30 天签到日历条带**（账户行 × 天列，数据 = ledger 真实 run）；
  ② **流量 KPI 内嵌水位条**（最低 remaining/total，低水位色只随 core `quota_low`
  谓词，红线 2）；③ **「下次班次」卡**（替代「最近一条日志」卡：全应用
  `schedule_times` 并集取下一个未来时刻，主数字 HH:MM，sub = 分钟倒计时 +
  今日剩余班次数，跨午夜取明早最早；无排班如实显示「未排班」）
- **仪表盘双栏重排（v6.3，2026-11-16 用户裁决，参考清新工作台风）**：
  KPI 行（v7 图标片 + 占比环）→ **双栏网格**（左：待办 TodoRail 三节；
  右 300px：**快捷入口** + **班次时刻**）→ 签到条带通栏收尾；
  ≤900px 随侧栏断点转单列。快捷入口 = **纯导航四片**（导入应用/去领取/
  去采集/看日志，emit navigate 复用既有 hash 路由，零新端点零跨页动作）；
  班次时刻卡 = `schedule_times` 并集升序逐行，「未到/已过」如实标注，
  下一个未来时刻高亮，无排班如实留白。新组件 `QuickPanel.vue` 承载右栏
- **响应式四档（v8.1，2026-11-18 用户裁决「界面没有自适应」）**：
  - 壳层：>900px 侧栏 + 内容区居中（`max-width: 1160px` + `margin: 0 auto`）；
    ≤900px 顶条两行网格、导航改 `flex-wrap: wrap`（换行铺满，不再横向滚动藏菜单），
    内容区 `width: 100%`。**纵排下禁止给内容区加 auto 边距**——交叉轴 auto 边距
    会阻止 stretch，内容块按内容宽度撑开、直接溢出屏宽（账户页横滚的真正成因）
  - 平台表：≤1180px 收「能力」→ ≤980px 收「平台类型/版本号」→ ≤760px 收
    「账户数/账户状态」并取消横向滚动，极窄屏只留「编码/名称/状态/调度/操作」5 列
  - 账户矩阵：≤900px 收「额度/凭据/最近操作」→ ≤760px 收「平台名」（账户 ID
    前缀已是平台编码），动作列保底 4.75rem；失败原因两行封顶省略，全文进账户详情
  - 行内动作：≤900px 统一 2×2 网格 + `white-space: nowrap`（横排会被列宽挤掉
    尾部按钮，纵向堆叠四行又把表格拉得又长又稀）
  - 验收口径：655px 视口下六页 `documentElement.scrollWidth == clientWidth`，零横向滚动
- 状态诚实：不把「已请求」渲染成「已领取」；结果渲染只消费 core 出产的分类谓词；
  待办栏只汇报系统真做过的动作
- 页面规格见 [A3-01 v2](specs/application/A3-01-信息架构与核心页面.md)
  （按 A1-03 §4 展开）

## 布局：内容区左贴侧栏（2026-11-18 改版）

- **问题**：`.content` 原为 `max-width: 1160px; margin: 0 auto`——宽屏（1920）下可用宽 1704，
  居中后侧栏与内容之间空出 272px，"两栏隔得老远"。这是「限制正文可读宽度」的经典做法，
  代价是把留白塞进了两栏之间（视觉上把侧栏和内容割开）。
- **改法**：`max-width: 1440px; margin-right: auto`——内容紧贴侧栏（间距=内容区左内边距 24px），
  留白全部推到页面右缘；上限 1160→1440，让表格页多一列时不至于刚过 1160 就横滚。
- **窄屏（≤900，侧栏变顶部横条）**：`width: 100%; margin-right: 0`，纵排不受影响。
- **未采用**：完全铺满（表格列被拉宽、行长过长）；仅调 padding（两侧仍对称、空白仍夹在中间）。

## 弹层表单：分组纵排 + 前缀类名（2026-11-18）

- **问题**：自定义平台弹层被判定「太乱」——字段下一条条横线、标签居中、两列输入框宽窄不一、
  说明文字互相压字。
- **根因（两个叠在一起）**：
  1. 组件用了与全局 `styles/ui.css` 同名的 `.field`（设置件：`display:flex; justify-content:space-between;
     border-bottom:1px solid`）和 `.row`（列表行）——表单被染成横排 + 下划线，标签被 `space-between` 推到中间。
  2. 两组接口块用 `auto-fit minmax(300px,1fr)` 横排两列，列宽随内容伸缩、各组高度不等，纵向无法对齐。
- **改法**：四段分组（基本信息 / 状态查询 / 领取请求 / 调度）；`基本信息` 组内两列 `repeat(2,minmax(0,1fr))`，
  接口与调度组单列纵排（方法下拉定宽 76px + URL 占满）；字段一律 `flex-direction:column` + `align-items:start`
  （不用 grid，避免被父级拉伸把 label/input 之间的 gap 摊开）；类名统一 `cpf-` 前缀。
- **未采用**：继续横排两列接口块（窄卡片下永远挤）；只调 gap/padding（治不了撞名）。
