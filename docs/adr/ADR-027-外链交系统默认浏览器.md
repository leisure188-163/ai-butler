# ADR-027 · 外链交给系统默认浏览器（桌面壳拦截 + web 同源派生）

- **状态**：Accepted
- **日期**：2026-11-18
- **决策者**：用户
- **关联**：A3-01 §2 系统设置（关于）/ A1-02（桌面壳 Electron）/ conventions/00（禁止写死端口）

## 背景

设置页「关于」有两处外链：仓库（Gitee）与接口文档。用户反馈「点链接没有跳到系统默认
浏览器，跳转的好像不对」。排查结论：

1. **接口文档写死** `http://127.0.0.1:8000/docs`——dev 下 8000 只是 vite 代理的目标；
   换端口起 server、或用桌面 sidecar（随机端口、同源伺服 `/docs`）时，这个链接指向
   的不是当前这套服务。
2. **桌面壳（`apps/desktop/main.js`）没有外链策略**——Electron 默认把
   `target="_blank"` 开成壳内新窗口/新标签，点击后应用窗口被顶掉或落在壳内，不符合
   「点链接离开应用」的预期。
3. **纯浏览器打开 web（如 localhost:5173）时无法指定用哪个浏览器**：页面只能发起
   导航，新标签留在当前浏览器；「换成系统默认浏览器」是浏览器/OS 层行为，网页无权干预
   （这是能力边界，不是缺陷）。

候选：①只加「复制链接」按钮——绕开问题但用户仍要手动粘贴；②写死改成
`window.location.origin` 派生的同时保留壳内打开——治不了"落回应用"；③同源派生 +
桌面壳 `shell.openExternal` 拦截——选③。

## 决策

**web 端链接同源派生，桌面壳把外链交给系统默认浏览器**，流程要点：

1. 接口文档地址由 `utils.docsUrl()` 按 `window.location.origin + "/docs"` 派生，
   不写死 host/port（红线：项目变量不散落硬编码）。dev 由 vite 代理 `/docs` 与
   Swagger UI 自拉的 `/openapi.json` 转发到主控 server；生产与 sidecar 同源直接命中。
2. 桌面壳（唯一能真正选择浏览器的载体）：
   - `setWindowOpenHandler`：**deny 一切新窗口**并把 URL 交给 `shell.openExternal`；
   - `will-navigate`：跨源整页跳转 `preventDefault` 后交 `shell.openExternal`，
     同源导航（hash 路由、`/docs`）留在壳内；
   - 只放行 `http:`/`https:`，其他 scheme 不猜、不外抛，记一条 `console.error`。
3. 纯浏览器场景如实告知边界：新标签沿用当前浏览器；要"跳出系统默认浏览器"必须用
   桌面壳（Electron）或手动复制链接。

**排除项**：不做自定义协议注册（跨平台注册成本高、且多数浏览器仍会先拦一道确认）；
不改浏览器默认浏览器设置；不为外链新增"复制链接"按钮（当前两处链接均可直接选中复制）。

## 后果

**正面**：

- 桌面壳里点任何外链（仓库、接口文档、以及未来新增链接）都离开应用、落到系统默认浏览器
- 接口文档地址随部署形态自证（dev 5173 / 生产 8000 / sidecar 随机端口都对）
- 壳内不再被外部站点顶掉当前页面，`nodeIntegration: false` 的安全边界保持不变

**负面/约束**：

- 纯浏览器访问时"跳出默认浏览器"仍做不到，只能靠桌面端；文档与答复须如实说明
- 桌面壳多一处策略代码，新增外链无需逐个登记即可生效（统一走 window-open/导航拦截）
