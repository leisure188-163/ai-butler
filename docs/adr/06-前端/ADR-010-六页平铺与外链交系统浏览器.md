# ADR-010 · 六页平铺，外链交系统默认浏览器

- **状态**：Accepted
- **日期**：2026-11-14（2026-11-19 页名改词；2026-11-18 外链边界）
- **决策者**：用户（页名级换词随六页 IA 一次到位；外链要求「跳到系统默认浏览器」）
- **落地文档**：A1-03 §3/§4（词表）、A3-01 §2（系统设置）/§3（待办入口）
- **关联**：ADR-014（浏览器边界与 Origin 拦截）、conventions/00（禁止写死端口）

## 背景

信息架构要回答两个问题：用户打开应用第一眼看到什么、每个动作放在哪。裁决：
**签到概览作为默认页只回答「今天有事要做吗」**；导入是平台层动作、领取/体检是账户层动作、
待办是签到概览内容而非独立页。

外链一侧的问题是设置页「关于」两处链接（仓库 Gitee 与接口文档）点开不跳系统默认浏览器：

1. **接口文档写死** `http://127.0.0.1:8000/docs`——dev 下 8000 只是 vite 代理的目标；换端口
   起 server、或用桌面 sidecar（随机端口、同源伺服 `/docs`）时，链接指向的不是当前这套服务。
2. **桌面壳没有外链策略**——Electron 默认把 `target="_blank"` 开成壳内新窗口/新标签，
   点击后应用窗口被顶掉或落在壳内，不符合「点链接离开应用」的预期。
3. **纯浏览器打开 web 时无法指定用哪个浏览器**：页面只能发起导航，新标签留在当前浏览器；
   「换成系统默认浏览器」是浏览器/OS 层行为，网页无权干预（能力边界，不是缺陷）。

候选：①只加「复制链接」按钮——用户仍要手动粘贴；②改成 `window.location.origin` 派生但保留
壳内打开——治不了"落回应用"；③同源派生 + 桌面壳 `shell.openExternal` 拦截——选③。

## 决策

### 1. 六页平铺（页名 2026-11-19 改词，hash 不变）

侧栏 = **签到概览（默认）/ 平台管理 / 账户管理 / 用量管理 / 运行日志 / 系统设置**，
规范 hash = `#/dashboard`、`#/platforms`、`#/accounts`、`#/traffic`、`#/logs`、`#/settings`
（`accounts`/`settings` 沿用原链；`apps`→`platforms`，旧 `#/apps` 直链不在重定向表内，
会落回默认页）。

- **重定向表 v2**（7 条旧链，命中 `replaceState` 静默重写）：`#/home`→签到概览、
  `#/alerts`→签到概览、`#/wallet`→账户管理、`#/card`→账户管理、`#/radar`→用量管理、
  `#/usage`→用量管理、`#/log`→运行日志。
- **职责重排**：待办栏三节整体从账户页迁入签到概览；导入入口与「一键导入（n）」归平台管理页；
  领取（含一键领取（n）/批量/体检）留在账户管理页；提醒角标改挂「签到概览」项，
  计数口径（待处理 + 非正常账户 + 临期凭据）零变化。
- **签到概览三块**：今日一句话结论（core 出产的结论谓词）、TodoRail 三节、速览四行
  （账户健康分布 / 今日自动动作 / 流量速览 / 最近一条日志）。全部复用现有数据，
  **不新增端点**，聚合走前端 computed。
- **平台管理页**：六列表（平台 / 能力 / 时间表 / 账户数 / 状态汇总 / 动作）+ 虚线邀请行
  「＋ 导入 {平台名}」+ 行展开跳转账户；数据取自契约既有 `PlatformOut`（含 `account_ids`，
  只做计数展示，**不实现多账号操作面**——多 profile dock 取证结论见 A2-02 §9）。
  另含「未导入的平台（N）」区块与「同步平台」按钮（见 ADR-031）。
- **顶栏与主题**：单行「AI 智能助手管家 + Butler」，≤900px 顶条同样显示主名；
  主题显示名「纸墨 / 墨夜 / 晨雾」，提醒角标口径不变。

### 2. 外链：web 同源派生，桌面壳交系统浏览器

1. 接口文档地址由 `utils.docsUrl()` 按 `window.location.origin + "/docs"` 派生，不写死
   host/port（红线：项目变量不散落硬编码）。dev 由 vite 代理 `/docs` 与 Swagger UI 自拉的
   `/openapi.json` 转发到主控 server；生产与 sidecar 同源直接命中。
2. 桌面壳（唯一能真正选择浏览器的载体）：
   - `setWindowOpenHandler`：**deny 一切新窗口**并把 URL 交给 `shell.openExternal`；
   - `will-navigate`：跨源整页跳转 `preventDefault` 后交 `shell.openExternal`，同源导航
     （hash 路由、`/docs`）留在壳内；
   - 只放行 `http:`/`https:`，其他 scheme 不猜、不外抛，记一条 `console.error`。
3. 纯浏览器场景如实告知边界：新标签沿用当前浏览器；要"跳出系统默认浏览器"必须用桌面壳
   （Electron）或手动复制链接。

**排除项**：不做自定义协议注册（跨平台注册成本高，且多数浏览器仍会先拦一道确认）；
不改浏览器默认浏览器设置；不为外链新增"复制链接"按钮。

**影响面**：仅 `apps/web/src/` + `apps/desktop/` + 文档；数据接口与端点不变（契约零改动）；
不引 vue-router / pinia / 新依赖。

## 后果

**正面**：

- 页名与现行词表对齐，签到概览作为默认页回答「今天有事要做吗」，账户页是纯矩阵工作台
- 组件按页拆分，`MatrixTable` 单件承载矩阵交互，符合 conventions/03 一业务域一模块
- 桌面壳里点任何外链都离开应用、落到系统默认浏览器；接口文档地址随部署形态自证
- 壳内不再被外部站点顶掉当前页面，`nodeIntegration: false` 的安全边界保持不变

**负面/约束**：

- 兼容直链在地址栏会静默重写为规范 hash（用户可见）；书签/外部链接需接受这一变化
- 六页的「平台 / 账户」数据来自同一批端点，切换页面不额外发请求，数据新鲜度由壳的自动刷新
  轮询保证
- 应用页「账户数」只做展示，多账号的导入/切换操作面待连接器逐家取证后立项
- 纯浏览器访问时"跳出默认浏览器"仍做不到，只能靠桌面端；文档与答复须如实说明
- 桌面壳多一处策略代码，新增外链无需逐个登记即可生效（统一走 window-open/导航拦截）
