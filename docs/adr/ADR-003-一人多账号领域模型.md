# ADR-003 · 一人多账号领域模型

- **状态**：Accepted（随 core 领域模型落地；实施细则见
  [A1-05](../specs/architecture/A1-05-按业务域重写总设计.md) §3 与
  [A2-04](../specs/domain/A2-04-accounts域.md)）
- **日期**：2026-11-13
- **决策者**：用户
- **关联**：[ADR-002](ADR-002-core按业务域分包.md)（五域分包）、
  [ADR-005](ADR-005-连接器target级端口路由.md)（target 级端口路由）、
  A2-01 / A2-04（领域与账户域 spec）

## 背景

产品最核心的诉求是「**一个人多个账户**」：同一人在同一 AI 应用平台
（如 Trae、豆包）常有多个账号，需要分别领取/计量/调度。
领域模型必须原生按「应用下账户集合」建模，矩阵 UI 天然按「行 = 账号」
组织，多账号即多行；缺口只在模型与契约。

## 决策

1. **Account 是应用下集合**：一个 Connector/应用可挂 N 个 Account；
   `account_id` 为唯一键，编址 = 所属应用 + 账号标识（`account_key` 缺省 `"main"`）。
2. **target 编址 = 应用 + 账号**：裸应用 id 兼容为首账号，MCP/CLI 既有调用不断。
3. **import 返回多账号**：连接器 dock/导入枚举本机多 profile/多开会话，逐账号入库。
4. **幂等/调度/领取/用量按账号粒度**：班次 Run 幂等回放、领取队列、
   `is_quota_low` 等谓词输入随账号隔离。
5. **凭据按账号隔离**：vault 内凭据绑定 account，不按应用共享。

## 影响面

- `packages/core`：领域模型（Account 聚合、编址）、usecases 幂等键。
- `packages/engine`：bridge 装配（一应用多账号端口路由）、连接器
  dock/导入/采集的多账号枚举。
- `apps/server`：契约字段 `account_key` / `account_ids`、import 返回形状
  → SDK 再生成 + web/MCP 侧类型随之（契约先行红线 4）。
- web：矩阵天然多行，无需 IA 变更。

## 风险与开放问题

- **同应用多开的会话隔离**：各客户端多 profile/双开的本机取证与隔离
  方案未定（部分客户端 v20 加密已定性不可解，见 A2-03 §7.7）。
- 各连接器幂等语义按账号重验（领取时间表/限频按账号还是按设备）。
- MCP 三工具的 target 语义随账号维度同步（query_quota/query_usage/claim_now）。
