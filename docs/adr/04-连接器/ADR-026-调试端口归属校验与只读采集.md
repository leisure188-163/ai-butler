# ADR-026 · CDP 端口先校验归属，只读采集不碰界面

- **状态**：Accepted
- **日期**：2026-11-18
- **决策者**：用户
- **关联**：ADR-007（豆包 9222 与 cdp_probe dock）/ A2-02 §7/§8/§10 / agentrouter PROTOCOL §4/§5

## 背景

平台页「导入」按 manifest 能力分发到连接器 dock。agentrouter 的网页通道把调试端口写死
`9222`，而 9222 在本机归**豆包客户端**（ADR-007 取证）。结果：目标页未打开时 `open_page`
会在豆包客户端窗口里创建 `https://ps.air-outer.com/console` 页面并可能拉到前台；「导入全部」
按 platform_code 排序，`agentrouter` 排第一，一点就弹豆包窗口。观感像「点接入就跳出豆包浏览器」，
且等于让第三方站点跑在豆包客户端窗口里。

另一条链路：平台行在已接入后按钮变为「刷新」，点它就**豆包客户端窗口弹到前台**。排查：
`POST /api/v1/platforms/{target}/import`（「刷新」的落点）→ `_import_one` → 导入后顺带
`collect_usage` → doubao 用量端口取会话 Cookie 时，若无活动页则调用
`channel.open_activity()`（`Target.createTarget`）**在客户端里新开一个页面**。Chromium 系
客户端新建页面会把应用窗口拉到前台，于是「读额度」变成了「抢焦点」。实测取证：修复前点
刷新/采集，9222 target 数增加且豆包窗口置前；修复后同样操作 target 数不变、前台应用不变。

约束与候选：

| 主题 | 候选 | 取舍 |
|---|---|---|
| 端口 | ①只改 agentrouter 常量 ②全部改每连接器 env ③env 可覆盖 + 使用前归属校验 | ①换机器/换端口即复发；②配置面变大但误配仍污染客户端窗口；**取③** |
| 采集 | ①先探测活动页，没有就跳过 ②`open_activity` 后立刻 `closeTarget` ③改浏览器级 `Storage.getCookies` | ①额度会长期采不到；②仍会闪一下窗口并打断用户；**取③** |

其他约束：用量采集是多链路自动触发的（导入顺带、每日 `start_usage_scans`、手动
`POST /usage/collect`），用户不在场，任何界面动作都是意外干扰；「切号要聚焦」是另一回事
（Radix 弹层失焦打不开，`Page.bringToFront` 属用户显式领取/切号的必要动作，不能一并去掉）；
不引入 vault 存 Cookie（ADR-007 零凭据设计），仍是运行时现取现用。

## 决策

### 1. 调试端口可配置 + 使用前归属校验

1. 端口由连接器自持 env 覆盖，缺省值保持旧契约（agentrouter：`AGENTROUTER_CDP_PORT`，
   缺省 9222）；非法值显式报错，不静默回缺省（红线 5）。
2. 归属校验放 `web_ui` 通用底座：`require_browser_port(channel)` 读页面 target 的 scheme，
   出现浏览器不可能承载的私有协议（如 `doubao://`）→ `PortNotBrowser`，连接器转
   `BrowserPortError` 显式失败；**绝不往客户端应用窗口里开页**。
3. 校验只看 target 形状（进程归属），不看站点登录态；页面为空放行（空白/刚启动的浏览器由
   `open_page` 按真实错误上报）。
4. `run()` 语义：端口不可用 = `FAILED`（环境问题），不转 `NO_AUTH`/relogin 待办；dock 语义：
   如实进 `DockOutcome.issues`，由「导入」结果直接展示。

**排除项**：不自动拉起/扫描备用浏览器端口（端口归属必须可预期，避免再次劫持别的客户端）；
不把 9222 从豆包手里"抢回来"——豆包主链路优先，agentrouter 需另起专用浏览器
（带 `--remote-debugging-port` 并登录站点）。

### 2. 只读采集不产生界面动作

1. 用量/额度等只读数据的会话凭据走**浏览器级** `Storage.getCookies`
   （`CdpChannel.storage_cookies(domain)`），经 `/json/version` 的 `webSocketDebuggerUrl`
   连浏览器级会话；不 `attach` 页面、不 `open_activity`、不 `Page.bringToFront`、
   不 `Target.createTarget`。
2. 连接器侧过滤域（doubao 取 `doubao.com`），同名 Cookie 先到先得；取不到会话 Cookie 显式
   报错（客户端可能未登录），不静默空采。
3. 界面动作**只允许**出现在用户显式触发的写操作里：领取/签到、切号（`switch.py` 的
   `Page.bringToFront`）、`dock` 的自动拉起（ADR-007 决策 5）。这些路径必须保持原有聚焦语义，
   本决策不改变它们。
4. `import` 顺带采集的语义保留——修的是采集**怎么取 Cookie**，不是删掉采集。

**排除项**：网页类连接器（浏览器 CDP）不适用浏览器级限制之外的额外约束，但其页面读取同样
不得新开用户不可见的页面来「顺便」采集；登录态过期的重登动作仍归用户（ADR-007 登录边界）。
后续新增只读采集必须遵守本决策；若某产品只能靠页面 DOM 取数，需先裁决「是否允许建页」，
不得默认 `open_activity`。

## 后果

**正面**：

- 「导入」不再把外站页面开进豆包客户端窗口；误配时给出可执行指引（env + 专用浏览器）
- 端口假设显式化：换机器/多浏览器并存只改 env，不动代码
- 刷新/每日采集/批量导入都不会再把客户端窗口拉到前台，用户可继续做别的事
- 采集不再依赖「有没有活动页」，关掉活动页也能拿到额度流水；少一次建页+附着，更快更少干扰

**负面/约束**：

- 想用 agentrouter 时必须准备一个专用浏览器实例（独立 `--user-data-dir` + 调试端口），
  并保持站点登录——多一步运维
- 缺省 9222 仍与豆包冲突：不配 env 时 agentrouter 导入会稳定失败（显式报错，非静默）
- `Storage.getCookies` 是浏览器级域，需保证 `/json/version` 暴露 `webSocketDebuggerUrl`
  （Chromium 111+ 实测有；缺失时显式 `CdpError`）
- 拿到的 Cookie 是域内全量（含子域），连接器必须自己按域过滤，避免把别的站点凭据带进请求头
