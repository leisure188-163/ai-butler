# ADR-021 · 表名域前缀纪律与平台落册（acc_platform）

- 状态：已采纳（2026-11-17 用户裁决）
- 背景：
  1. 现行表名是裸实体名（accounts/runs/audit），业务扩展后难辨域、表管理难；
  2. 平台（连接器家族）只活在内存 Registry（manifest 装载产物），没有表管理，
     web 名册每次都要穿连接器包拼装，后续拼装对接麻烦。
- 决策：
  1. **表名 = 域缩写前缀 + 单数实体**，全库统一：
     `acc_account` / `acc_platform` / `exe_run` / `usage_snapshot` /
     `usage_aggregate` / `usage_quota_ledger` / `usage_sample` /
     `health_state` / `vault_item` / `vault_history` / `audit_log`；
     索引名随表名同步。老表由各适配器 `ALTER TABLE RENAME` 幂等自迁移，
     旧索引随行 DROP（零数据丢失）。
  2. **平台落册**：新增 `acc_platform` 表（账户域托管），启动时组合根从
     manifest 抽纯数据 facts → `SyncPlatforms` 用例 → UPSERT + 缺失平台落
     `deprecated_at`（不删行）；`is_active` 用户开关；web `/platforms` 名册
     改读名册表 + 台账并账，删除穿连接器包拼装的路径逻辑（端零映射更纯粹）。
- 后果：`/platforms` 契约形状不变（SDK/前端零改动）；退役连接器下次启动
  自动落 deprecated（仍可从名册表追溯历史）。
