# ADR-033 账户模型扩展：冻结编址、身份/来源分离、凭据槽位与接入源

- 状态：已接受（2026-11-20 用户裁决）；**§1 编址部分已被 [ADR-034](ADR-034-账户主键不透明与source-key唯一.md) 取代**（存量账户已于同日彻底重置为不透明主键，新增 `source_key` 唯一锚点）。§2 身份分离、§3 槽位、§4 接入源继续有效。
- 关联：ADR-003（一人多账号）、ADR-025（昵称编址，其编址部分被本 ADR 取代）、ADR-029（凭据按账户隔离）、ADR-030（别名绑定真实身份）、ADR-034、A2-04、A2-09
- 触发：参考 magpie（yetone）与 cc-switch（farion1231）的账户/接入源模型后，发现本仓库把
  「身份 / 凭据 / 接入源」三条轴压在同一主键上，继续扩展会持续返工。

## 背景与证据

现状（8 个账户，5 个平台）：

- 身份轴：`account_id = {platform}:{account_code}`，存量账户的 `account_code` 取自昵称
  （`doubao_cn:逍遥酒鬼`、`qoder_cn:global-020dbc5a`）。昵称可变，编址却不可变；
  ADR-025 已自述「改昵称 → 编址漂移、重名撞唯一索引」的负面后果。
- 凭据轴：`vault_item` 主键 `(account_id, kind)`，一个账户一种凭据只能存一份，
  第二个 API key 无处安放；`vault_history` 也只按 kind 归档。
- 接入源轴：`plat_platform.platform_kind` 只有 `web/client` 两类，表达的是「产品形态」，
  不是「怎么连」。`custom_platforms` 是声明式网页连接器（cookies + 请求模板），
  不适合 API key 型 provider（OpenAI 兼容网关、本地 Ollama、Anthropic 反代）。

直接后果（已在库中取证）：

- `health_state` 残留旧键 `acct:doubao_cn:main`、`acct:doubao_cn:u66b1e22d`，与新编址并存。
- 前端 `accountLabel` 自行兜底，`WorkBuddy CN` 显示成 `main`；显示口径分散在前端。
- 没有 `POST /accounts`，新账户只能靠连接器导入；没有 `is_active`/`base_url` 写端点。
- 账户上没有 `last_seen_at`、没有来源标记，无法区分「客户端发现」与「用户手建」。
- 没有 cooldown / 优先级 / 额度耗尽等运行态，调度只能按时间轮询。

## 裁决

### 1. 编址冻结（只冻结新写入，不迁移存量）

- `account_id` 创建即冻结，`account_code` 是创建时确定的不可变锚点。
- 昵称、邮箱、备注一律**不进 `account_code`**，只进显示层。
- 存量 8 个账户的 `account_id` 原样保留（含 `doubao_cn:逍遥酒鬼`），不做自动重建。
  昵称变化由 `identity_json.nickname` / `alias` 承载。
- `RegisterAccount` 命中既有账户时一律回放，不改号、不改名。
- 手建账户的 `account_code` 由端侧生成 `acc_<8hex>`（不可读但稳定），显示交给 `account_label`。

### 2. 身份与来源分离

`acc_account` 新增：

| 列 | 语义 |
| --- | --- |
| `identity_json` | `{nickname,email,uid,org,source_key}`；空对象 = 未知，不猜 |
| `origin` | `connector`（本机客户端导入）/ `manual`（用户手建） |
| `last_seen_at` | 最近一次连接器看到该账户的时间（运营字段，不参与编址） |

`source_key` 是连接器侧的稳定身份键（抖音 sec_uid、Qoder user.id、Trae device 号等），
用于「同一真实人再次被扫描到」的匹配；取不到时留空，**禁止用昵称兜底匹配**。

显示标签由 core 单源计算，不落库（SQL 规范禁止 `display_name` 通用名列）：

```
alias > identity.nickname > account_name 的「平台名 · 」后缀 > account_name > account_code
```

API 输出 `account_label`；web 不再自行拼装。

### 3. 凭据槽位（同账户同 kind 多份）

`vault_item` 主键改为 `(account_id, kind, slot)`，新增 `slot` / `label`：

- 默认槽 `slot=default`，后端引用仍是 `{account_id}:{kind}` → **存量秘密零迁移**。
- 非默认槽引用 `{account_id}:{kind}@{slot}`，轮换归档 `…@{slot}#{seq}`。
- `slot` 限 `[A-Za-z0-9_-]{1,24}`；`label` 只做显示（如「主 key」「备用 key」），不参与寻址。
- `CredentialPool.acquire(account, kind, slot=default)`；网关未指定槽时只取默认槽。
- 撤销支持整账户（全部槽）与单槽；删除账户 `purge` 清全部槽与历史。

### 4. 接入源（provider）层现在上

- `platform_kind` 扩展为 `web/client/relay/local/api`；语义是「怎么连」，不是「哪家产品」。
- `plat_platform` 新增 `base_url`、`protocol`、`models_json`、`origin`：
  - `protocol ∈ {openai}`（2026-11-20 修订：海外模型/协议不接入，当前也无法连外网，
    原 `anthropic/gemini` 词表收掉）；`models_json` 是声明可用模型列表。
  - `origin=connector` 由连接器 manifest 同步写；`origin=user` 由用户手建，**不参与
    `deprecate_missing`**（启动同步不会把用户接入源标退役）。
- 用户接入源没有 connector，不产生 claim/usage 端口，调度表为空；
  账号通过 `POST /accounts` 绑定，密钥通过槽位端点写入。
- 连接器平台与用户接入源共用 `account_id` 编址；一个接入源可挂多账户（多 key 多租户）。

### 5. 写端点补齐

- `POST /accounts`：手建账户（平台必须存在且未退役）；可带首份凭据。
- `PATCH /accounts/{id}`：`alias` / `account_name` / `is_active` / `base_url` / `identity`，
  不提供 `account_code`、`platform_code` 改写入口。
- `POST /accounts/{id}/credentials`、`DELETE /accounts/{id}/credentials/{kind}/{slot}`。
- `POST /platforms/providers`：手建接入源；`PATCH /platforms/{code}` 扩展
  `base_url` / `protocol` / `models`（仅 `origin=user` 可改）。

### 6. 本次不做

- 不做 `account_id` 迁移脚本（存量 id 保留；只保证新写入冻结）。
- 不做昵称 → 编址的自动重算、不做重复昵称自动加后缀。
- 不做网关协议互译 / 路由组 / 熔断 / 配额感知（magpie 的强项，属网关域下一阶段）。
- 不改连接器侧注册逻辑去回填 `source_key`（留给连接器域按平台逐家接）。

## 后果

正面：

- 改昵称、改显示名不再影响任何主键、凭据引用、台账外键。
- 同账户可并存多份 key，轮换/灰度/备用不需要建第二个账户。
- 用户可以在 Butler 里直接添加 API 型接入源（中转站、本地模型、官方 API），
  不再被「必须先有客户端连接器」卡住；这也是后续网关路由的挂载点。
- 显示口径收口到 core，前端与端侧不再各算一套。

负面 / 需接受：

- 存量 `qoder_cn:main`、`trae_cn:main`、`workbuddy_cn:main` 仍然不可读；需要用户在
  账户页补昵称/别名（显示层解决，不动库）。
- `account_label` 不保证唯一：两个账户可以都叫「逍遥酒鬼」。重名消歧留给后续
  「标签 + 短码」方案，本次不引入唯一约束。
- 旧 `vault_item` 需要一次表重建（SQLite 无法直接改主键）；默认槽保留旧 backend ref，
  所以秘密不迁移，只搬元数据行。
- 手建账户的 `acc_xxxxxxxx` 不好看；这是冻结编址的代价，显示由 label 承担。

## 回收清单

- A2-04 补列清单、端口签名、`CreateAccount/UpdateAccount/AddCredential/RevokeCredential` 用例。
- A2-09 补 `PLATFORM_KINDS`、接入源字段与 `CreatePlatform`。
- A4-01 补 `vault_item` 三列主键与槽位引用规范。
- web 账户页显示 `account_label`，补启停 / 地址 / 密钥槽位 / 手建账户入口。
- 平台页补「接入源」创建入口（relay/local/api）。
- 旧 `health_state` 陈旧键由一次性清理脚本处理（不属本 ADR 的写入路径）。
