# ADR-010 · 一人多账号领域模型

- **状态**：Accepted（2026-11-14 起由 [ADR-012](ADR-012-按业务域分包与核心从零重写.md)
  并入 core/engine 从零重写落地；实施细则见
  [A1-05](../specs/architecture/A1-05-按业务域重写总设计.md) §3 与
  [A2-11](../specs/domain/A2-11-accounts域.md)）
- **日期**：2026-11-13
- **决策者**：用户（层① web 全做 + 层② 占位 ADR 的范围裁决）
- **关联**：ADR-003（target 级端口路由）、ADR-009（矩阵改版）、A2-01/A2-02（领域与连接器规范）

## 背景

产品最核心的诉求是「**一个人多个账户**」：同一人在同一 AI 应用平台
（如 Trae、豆包）常有多个账号，需要分别签到/领取/计量/调度。当前 M1
契约为**一应用一账户**（Account 是应用下的单例；矩阵改版时层叠交互按
单账户契约裁掉）。矩阵 UI 已天然按「行 = 账号」组织，多账号即多行，
界面层无需再改；缺口在领域模型与契约。

## 决策（方向）

1. **Account 从应用单例变为应用下集合**：一个 Connector/应用可挂 N 个
   Account；`account_id` 继续作唯一键，新增「所属应用 + 账号序/标识」编址。
2. **target 编址演进**：现 target = 应用 id；演进为 target = 应用 + 账号标识
   （兼容层保留裸应用 id = 首账号，避免 MCP/CLI 既有调用断裂）。
3. **import 返回多账号**：连接器 dock/导入需枚举本机多 profile/多开会话，
   逐账号入库；capability 申报不变。
4. **幂等/调度/领取按账号粒度**：当日班次 Run 幂等回放、签到与领取队列、
   用量采集均以 account 为单位；`is_quota_low` 等谓词输入随账号隔离。
5. **凭据按账号隔离**：vault 内凭据绑定 account，不再按应用共享。

## 影响面

- `packages/core`：领域模型（Account 聚合、编址）、usecases 幂等键。
- `packages/engine`：bridge 装配（一应用多账号端口路由）、连接器
  dock/导入/采集的多账号枚举。
- `apps/server`：契约变更（accounts/runs 键位、import 返回形状）→
  SDK 再生成 + web/MCP 侧类型随之（契约先行红线 4）。
- web：矩阵天然多行；无需 IA 变更（ADR-009 已预留）。

## 风险与开放问题

- **同应用多开的会话隔离**：各客户端多 profile/双开的本机取证与隔离
  方案未定（部分客户端 v20 加密已定性不可解，见 A2-03 §7.7）。
- 各连接器幂等语义按账号重验（领取时间表/限频是否按账号还是按设备）。
- 契约变更波及 MCP 三工具（query_quota/query_usage/claim_now 的 target 语义）。
