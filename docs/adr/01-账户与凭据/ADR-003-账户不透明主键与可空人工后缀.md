# ADR-003 · 账户用不透明主键 + source_key 锚点 + 可空人工后缀

- **状态**：Accepted（已落地；实施细则见 A1-05 §3 与 A2-04）
- **日期**：2026-11-13（2026-11-18～11-20 编址与显示层三次收敛）
- **决策者**：用户
- **关联**：ADR-001（六业务域分包）、ADR-005（target 级端口路由）、ADR-013（会话观测）、
  A2-01 / A2-04（领域与账户域 spec）、A4-01 §1（凭据保险库）

## 背景

产品最核心的诉求是「**一个人多个账户**」：同一人在同一 AI 应用平台（如 Trae、豆包）常有多个
账号，需要分别领取/计量/调度。领域模型必须原生按「应用下账户集合」建模，矩阵 UI 天然按
「行 = 账号」组织。

真库同步后暴露了编址问题：`account_id` 混入平台名、昵称、`main` 占位与哈希；
`RegisterAccount` 按拼接 id 幂等回放，导致同昵称两真人被静默合并、同一人改昵称重复建账户；
`identity_json` 全 NULL，唯一性建立在展示名上而非真实人上。名称也曾被拼成
「Doubao CN · 逍遥酒鬼」这类带平台前缀的形态，既不可靠也不可改。

## 决策

### 1. account_id 不透明、不可变

- 新账户 id 固定 `acc_<8hex>`（uuid4 前 8 位查重），不从平台、昵称、编码推导。
- 存量 id 已一次性重发（`scripts/migrate_account_ids.py`，默认 dry-run、`--apply` 写库；
  依赖表 vault/exe/usage/audit/health/routes 全量改写，迁移前整库备份，`integrity_check=ok`）。
- 旧复合 id 只保留在备份表与历史审计行，不再作为新写入。

### 2. source_key 是唯一身份锚点

- 独立列 `source_key TEXT NOT NULL DEFAULT ''`；唯一约束
  `UNIQUE(platform_code, source_key) WHERE source_key <> ''`（空串不占用）。
- 注册认回顺序：① source_key 命中 → 认回（改名改 code 都不新建）；② 未命中 → 按
  `(platform_code, account_code)` 查；③ code 命中但两边 source_key 都非空且不同 →
  `AccountConflict` 显式拒绝，绝不静默复用；④ 存量 `legacy:<code>` 占位键首次真实 dock 时
  就地吸收。
- 连接器回传口径：豆包 `sec_uid`、Qoder `user.id`、Trae `userId`（设备号）、
  WorkBuddy `account.uid`、AgentRouter `github_<user_id>`；取不到则留空，
  **禁止用昵称兜底匹配**。

### 3. 身份与来源分离

- `identity_json`（nickname/email/uid/org；`source_key` 已独立列不重复写入）；空身份落
  NULL，不猜。
- `origin`：`connector`（本机客户端导入）/ `manual`（用户手建）；`last_seen_at` 为运营字段，
  不参与编址。

### 4. 显示层：account_name / alias / account_label

- **account_name 只描述账户自身**（客户端昵称/用户名/邮箱，取不到 = `未命名账户`），
  **禁止拼接平台名**；平台由列表分组/徽标表达。
- **alias 别名绑定真实身份**：用户可编辑显示名，≤40 字，空串 = 清除；
  `PATCH /accounts/{id}` 只写 alias 一列，404/400 显式报错。纯显示层：不参与鉴权、调度、
  run target，避免"改名字把领取打到别的账户"。
- **显示标签 core 单源**（`account_label`，不落库，前端不自行拼装）：
  `alias > identity.nickname > account_name > account_code > account_id`。不保证唯一。

### 5. account_code = 可空人工后缀

- 同步账户一律留空（`''`）= 尚未关联登录账户；用户在账户详情手动填写/清空。
- 索引 `UNIQUE(platform_code, account_code) WHERE account_code <> ''`：空 code 可多条共存，
  非空平台内唯一。
- **永不参与连接器幂等**：同步幂等按 `(platform_code, source_key)` 认回，
  无 source_key 时用 `device_ref` 兜底。
- `UpdateAccount` 允许改 code；`account_id` 与 `platform_code` 冻结。
- 依赖 `(platform, code)` 的旧路径（裸平台发起 Run）改为：单账户自动选中，多账户必须显式
  传 `account_id`；`RunOut.account_code` 返回当前人工后缀。

### 6. 编址恒等式

- 编址 = 平台 + `account_id`；裸 `platform_code` 发起 Run 时单账户自动选中，多账户必须显式
  传 `account_id`（无 `main` 兼容槽）。
- 幂等键 = `(kind, account_id, 窗口)`；领取队列、`is_quota_low` 等谓词输入随账户隔离。

### 7. 凭据按账户隔离，槽位不进账户键

- `vault_item` 主键 `(account_id, kind, slot)`，默认槽 `default`——存量秘密零迁移；非默认槽
  引用 `{account_id}:{kind}@{slot}`，轮换归档 `…@{slot}#{seq}`。
- `slot` 限 `[A-Za-z0-9_-]{1,24}`；`label` 只做显示。`CredentialPool.acquire` 未指定槽时取
  默认槽；撤销支持整账户与单槽；删除账户 purge 全部槽与历史。

### 8. 接入源层

- `platform_kind` 扩为 `web/client/relay/local/api`（语义 =「怎么连」）；
  `plat_platform` 新增 `base_url/protocol/models_json/origin`。`protocol ∈ {openai}`。
- `origin=user` 接入源不参与 `deprecate_missing` 启动退役；无 connector，不产 claim/usage
  端口；账号走 `POST /accounts` 绑定，密钥走槽位端点。
- 写端点：`POST /accounts`（可带首份凭据）、`PATCH /accounts/{id}`、
  `POST/DELETE /accounts/{id}/credentials...`、`POST /platforms/providers`、
  `PATCH /platforms/{code}`（仅 `origin=user`）。

### 9. 网页会话通道每 profile 一账户

- 逐 profile 捕获：凑齐必需名单的 profile 各成一个账户槽（`CapturedProfile`），
  `browser_cookie` 通道统一生效（chatgpt_web / claude_web 共享，无 per-app 分支）。
- 账户键：profile 目录名即 `device_ref`（`butler_connectors/browser.py`：
  `device_ref=item.profile_dir`）——本机可核对事实，重扫按 `device_ref` 认回同一个 `acc_…`，
  不新建。
- 显示名：`account_name` = profile 目录名（取不到 = `未命名账户`），不拼平台名；
  `account_code` 一律留空，等用户后续人工关联。
- 同 profile 目录新旧布局并配（`Cookies` + `Network/Cookies`）按目录去重，首个库（路径序）
  获胜；逐 profile 隔离纪律不变：单库锁死/解不开记原因换下一个，全落空有事故报首个原因，
  无事故按未登录如实落榜。

**排除项**：账号同一性验证不做（不解密、不取 uid 明文，红线 5）；重复账号的重复槽是已知
代价，由领取幂等（服务端 ALREADY）兜底，不做去重合并；桌面客户端连接器
（trae/qoder/doubao/workbuddy）不适用——其多账号走各自取证后的 dock 接入。

## 影响面

- `packages/core`：账户聚合与编址、usecases 幂等键。
- `packages/engine`：bridge 装配（一应用多账号端口路由）、连接器 dock/导入/采集的多账号枚举。
- `apps/server`：契约字段 `account_ids`、import 返回形状 → SDK 再生成 + web/MCP 侧类型随之
  （契约先行红线 4）。
- web：矩阵天然多行，无需 IA 变更。

## 后果

- 账户唯一性由 `source_key` 承担：同一真人改名不再漂移，不同真人同昵称不再合并。
- 显示不再出现平台前缀；重复扫描不覆盖人工后缀；手建 `acc_xxxxxxxx` 不可读是冻结编址的
  代价，显示由 `account_label` 承担（不保证唯一）。
- 网页双 profile 会话都能用，UI「平台 → 账户」展开有了真实多账户数据源；若两 profile 是
  同一账号，矩阵出现重复行、领取第二个必 ALREADY——用户可见冗余，接受。
- 编键稳定性依赖「profile 目录名 = device_ref」：目录改名 = 新账户槽。
- 回滚路径：停服 → 备份库覆盖 `data/database/butler.db`；旧 `vault_ref` 未删除。

## 风险与开放问题

- **同应用多开的会话隔离**：各客户端多 profile/双开的本机取证与隔离方案（部分客户端加密
  已定性不可解，见 A2-03 §7.7）。
- 各连接器幂等语义按账号重验（领取时间表/限频按账号还是按设备）。
- MCP 三工具的 target 语义随账号维度同步（`query_quota` / `query_usage` / `claim_now`）。
