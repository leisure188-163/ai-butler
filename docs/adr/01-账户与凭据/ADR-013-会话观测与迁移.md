# ADR-013 · 会话观测与迁移（workspace 先行 · accounts 域编排）

- 状态：Accepted（2026-11-15 立项裁决）。**落地进度**：S1 只读观测已落地
  （`SessionSourcePort.scan_sessions` + `ScanSessions` 用例 + `trae_cn/sessions.py`）；
  S2 `session.migrate` 用例、`session-snapshots/` 快照与 CLI `session restore`
  **尚未实现**——本篇是待落地的裁决，不是现行事实。
- 关联：A1-01 §3 L4、A1-03 §8、A2-04 §2、plans/03

## 背景

R5 立项（plans/03）需先定概念与归属：L4「会话」≠ 登录态（凭据迁移 M1 已
做）；Session 实体与 SessionSourcePort 在 core 已留锚点但零装配；旧系统
无会话迁移知识（无 legacy oracle）。six 裁决点见 plans/03 §2。

## 裁决

1. **会话定义 = A3 分 kind**：`Session.kind ∈ {conversation, workspace}`。
   首批只做 **workspace（工作区/配置上下文）**——纯文件、低风控、回退
   容易；conversation（对话历史）逐家取证后再开（写风险高），实体层
   kind 字段一次到位防返工。
2. **首批家数 = trae_cn 先行、qoder_cn 次之**：声明式 HTTP 家、
   storage.json 形状 M1 已摸过，取证成本最低；doubao/workbuddy 视取证
   结果另行决定（doubao 写动作需逐次授权）。
3. **inject = 模板化上下文注入，用户确认后发送**：无 LLM 依赖、不发明；
   发送属写动作，逐次授权。
4. **server 级 = 只包装官方明示能力**：官方导出/同步开关，不逆向私有接口，
   超出即不做（YAGNI + 合规）。
5. **编排归属 = accounts 域**：`session.migrate` 用例（新 Action kind 走
   A2-01 §2 扩展）与快照回退同域自洽（Session 数据在 accounts 域）。
6. **回退形态 = 数据根 `session-snapshots/<account_id>/` 快照，保留 2 代，
   CLI `session restore` 为还原入口**；迁移前快照是硬承诺。

## 后果

- `Session` 实体补 `kind` 字段（frozen dataclass 增量，枚举 `StrEnum`，
  校验进 `__post_init__`）——core 改动随 S1 批次落地
- 正面：R5 动线可开工（S1 SessionSourcePort 实装 → S2 local 级迁移）；
  对话历史的风险被 kind 隔离，不阻塞首批
- 负面：首批能力范围收窄（只 workspace 级），产品文案需如实标注
  「可迁移 + 可回退，不承诺无缝」（A1-01 §6）
- 遵守：只读取证、ToS 边界、风控征兆停机（plans/03 §0 纪律不变）
