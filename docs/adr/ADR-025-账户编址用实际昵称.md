# ADR-025 · 账户编址用实际昵称

- **状态**：Superseded（编址部分被 ADR-033 取代：存量 id 保留、新写入冻结，昵称只进 identity/显示层；2026-11-20）
- **日期**：2026-11-18
- **决策者**：用户（honesty520 会话裁决）
- **关联**：ADR-003（多账户）/ ADR-007（决策 8 自动切号）/ PROTOCOL §5 身份登记簿

## 背景

多账户落地后，卡号（account_code）来源不统一：基线账户固定 `main`，第二账户用
sec_uid 派生（`u` + SHA256 前 8 位，如 `u66b1e22d`）。用户在仪表盘/台账看到的
`doubao_cn:main`、`doubao_cn:u66b1e22d` 无法直观区分是谁，与 qoder 全局账户
「global-<sha1(user.id)[:8]> + 邮箱命名」的实际信息风格也不一致。登记簿本身已
采集实际昵称（逍遥酒鬼 / Leisure520），只是没有用作编址。

候选：①维持占位（main + 派生）——不可读，被否；②用实际昵称编址，派生兜底——
被选中；③用 sec_uid 全串——稳定但完全不可读，被否。

## 决策

**账户编址（account_code）以实际昵称为准**，流程要点：

1. `resolve_account_key`：基线命中 → 基线昵称；登记簿 others 命中 → 条目昵称；
   未登记/昵称缺失 → sec_uid 派生兜底（编址必须有稳定唯一来源，绝不空缺）。
2. dock 落账：基线账户显式传 `account_code=昵称`、`account_name="Doubao CN · 昵称"`；
   其他账户同理（昵称缺失时 account_name 回退 DISPLAY）。
3. 切号定位（`resolve_target_identity`）：基线与其他账户同按 code 匹配，
   删除 `main` 字面量特判。
4. CLI `--account` 省略 = 该平台第一张卡（不假定 main 存在）。
5. 存量迁移（一次性）：`doubao_cn:main → doubao_cn:逍遥酒鬼`、
   `doubao_cn:u66b1e22d → doubao_cn:Leisure520`（含 usage_quota_ledger 引用）；
   **exe_claim 台账历史保留旧 account_id**（审计记录不可改写）。
   迁移前 DB 快照备份 `%TEMP%\butler-backup-pre-account-code.db`。

**排除项**（2026-11-18 修订：workbuddy 移出）：core 层 `RegisterAccount.execute`
的 `account_code="main"` 默认值保留——它是「无身份来源平台」的兜底语义
（trae/agentrouter 单账户场景）。**扩展（同日）**：workbuddy 的
`account.nickname` 实为加密信封（mac 真机核实），并非无身份来源——dock
追加密封解密取昵称作 account_code（ADR-008 决策 4 修订），存量一次性迁移
`workbuddy_cn:main → workbuddy_cn:大海`（acc_account + usage_snapshot 38 行；
exe_claim/audit_log 台账审计历史保留旧 id；迁移前备份
`/tmp/butler-backup-pre-wb-nickname-20261118-214353.db`）。helper.js 契约
扩展见 ADR-008 决策 2 修订。

## 后果

**正面**：

- 仪表盘/台账/CLI 卡号即人名，多账户一眼区分；与 qoder 实际信息风格对齐
- 登记簿、切号定位、落账三处编址语义统一（单一出口 `resolve_account_key`）

**负面/约束**：

- 用户改昵称 → 编址漂移：登记簿/dock 重跑会刷新 code，但旧 code 的卡与
  台账引用不自动跟随（需再跑一次迁移口径）；重名账户会撞唯一索引并显式报错
  （显式失败优于静默兜底，红线 5）
- 昵称含特殊字符时 CLI `--account` 需引号包裹（PowerShell/Bash 引用语义）
