# ADR-028 · 只读采集不产生界面动作

- **状态**：Accepted
- **日期**：2026-11-18
- **决策者**：用户
- **关联**：ADR-007（CDP 界面通道）/ ADR-026（调试端口归属）/ A2-02 §7、§10 /
  doubao_cn PROTOCOL §7.2

## 背景

用户反馈：平台行在已接入后按钮变为「刷新」，点它就**豆包客户端窗口弹到前台**。

排查链路：`POST /api/v1/platforms/{target}/import`（「刷新」的落点）→ `_import_one`
→ 导入后顺带 `collect_usage` → doubao 用量端口取会话 Cookie 时，若无活动页则调用
`channel.open_activity()`（`Target.createTarget`）**在客户端里新开一个页面**。Chromium
系客户端新建页面会把应用窗口拉到前台，于是「读额度」变成了「抢焦点」。实测取证：
修复前点刷新/采集，9222 target 数增加且豆包窗口置前；修复后同样操作 target 数不变、
前台应用不变。

约束：

- 用量采集是多链路自动触发的（导入顺带、每日 `start_usage_scans`、手动
  `POST /usage/collect`），用户不在场，任何界面动作都是意外干扰。
- 「切号要聚焦」是另一回事：Radix 弹层失焦打不开，`Page.bringToFront` 属用户
  显式领取/切号的必要动作，不能一并去掉。
- 不引入 vault 存 Cookie（ADR-007 零凭据设计），仍是运行时现取现用。

候选：①采集前先探测活动页，没有就跳过——额度会长期采不到（活动页常有、但用户
关掉就断）；②`open_activity` 后立刻 `Target.closeTarget`——仍会闪一下窗口且打断
用户当前页面；③改浏览器级 `Storage.getCookies`——不依附页面，选③。

## 决策

**只读采集不得产生界面动作**，具体边界：

1. 用量/额度等只读数据的会话凭据走**浏览器级** `Storage.getCookies`
   （`CdpChannel.storage_cookies(domain)`），经 `/json/version` 的
   `webSocketDebuggerUrl` 连浏览器级会话；不 `attach` 页面、不 `open_activity`、
   不 `Page.bringToFront`、不 `Target.createTarget`。
2. 连接器侧过滤域（doubao 取 `doubao.com`），同名 Cookie 先到先得；取不到会话
   Cookie 显式报错（客户端可能未登录），不静默空采。
3. 界面动作**只允许**出现在用户显式触发的写操作里：领取/签到、切号
   （`switch.py` 的 `Page.bringToFront`）、`dock` 的自动拉起（ADR-007 决策 5）。
   这些路径必须保持原有聚焦语义，本决策不改变它们。
4. `import` 顺带采集的语义保留——修的是采集**怎么取 Cookie**，不是删掉采集。

**排除项**：网页类连接器（浏览器 CDP）不适用浏览器级限制之外的额外约束，但其
页面读取同样不得新开用户不可见的页面来「顺便」采集；登录态过期的重登动作仍归
用户（ADR-007 登录边界）。

## 后果

**正面**：

- 刷新/每日采集/批量导入都不会再把客户端窗口拉到前台，用户可继续做别的事。
- 采集不再依赖「有没有活动页」，关掉活动页也能拿到额度流水。
- 少一次建页+附着，采集更快、更少干扰客户端状态。

**负面/约束**：

- `Storage.getCookies` 是浏览器级域，需保证 `/json/version` 暴露
  `webSocketDebuggerUrl`（Chromium 111+ 实测有；缺失时显式 `CdpError`）。
- 拿到的 Cookie 是域内全量（含子域），连接器必须自己按域过滤，避免把别的站点
  凭据带进请求头。
- 后续新增只读采集必须遵守本决策；若某产品只能靠页面 DOM 取数，需先裁决
  「是否允许建页」，不得默认 `open_activity`。
