# ADR-007 · 品牌更名 Kabao（卡包），业务语言采用市场白话

- **状态**：Accepted
- **日期**：2026-11-12
- **决策者**：hiclaw520 + AI
- **关联**：[A1-03 品牌与业务语言标准](../specs/architecture/A1-03-品牌与业务语言标准.md)（唯一事实来源）、
  A1-01（定位）、DESIGN-DECISIONS D1/D2/D3、ADR-002（协议字面量不动）、conventions/03（词表收编）

## 背景

用户裁决：原内部隐喻体系"没有市场通用性"，要做**通用的 AI 助手管家**，用**业务通用语言和
标准定义准则**统一系统，全部不合理处（文档 + 代码 + UI）都改。市场调研（2026-11-11）
证实：直接竞品 CreditDaddy 等（积分/额度/签到/账号管理）全用直述语言，且其 v0.3.0
更名时做了数据目录自动迁移——市场先例完整。

候选方案：①保留旧隐喻只做润色——用户已否决；②双语过渡（两套词并存）——
双词汇体系永久增加认知与维护成本；③**全深度一次到位**（选定）——
一次性改名 + 数据自动迁移，短痛换干净的单一词汇体系。

约束：187+ 触点；mac/Windows 双端并行开发；协议字面量与旧系统 oracle 对齐**不能动**。

## 决策

**品牌更名 Kabao（卡包），定位「通用 AI 订阅管家」（广度优先），业务语言全量市场白话**，要点：

1. **两层词汇原则**：协议词汇（Status 七字面量 CLAIMED/ALREADY/FAILED/NO_AUTH/PENDING/
   EXPIRED/SKIPPED——ADR-002 方言、oracle 对齐）**保留不翻译**，是 API 层契约；
   产品词汇（UI/CLI/文档）全量换市场白话。领域实体名（Account/Action/Run/Event）同属
   工程层不动。
2. **四条铁律**（圈外秒懂 / 一个概念一个词 / 隐喻限大众心智模型 / 工程术语不外溢 UI）
   与**核心词表 v1** 单源落 A1-03，并收编进 conventions/03 成为强制规范。
3. **全深度一次到位**：repo / Python 包 / CLI / env / 数据目录与库 / npm / UI / 文档
   全量改名——当前值清单见 A1-03 §6。
4. **数据自动迁移**：首次运行检测历史数据源自动搬移，历史文件保留不删，迁移幂等
   并写审计（A1-03 §7；先例 CreditDaddy v0.3.0）。

**明确排除项**：协议字面量与各连接器 PROTOCOL.md 业务码字典不动（叙事措辞可扫）；
A0-01 面向前代项目 auto-signin-kit，词表不适用；git 历史不改写；
品牌重塑不新增功能、不改 API 语义。

## 后果

**正面**：

- 用户可见语言与市场基线一致，圈外用户零学习成本，产品可被对比、可被传播
- 单一词汇体系，无双轨维护成本
- 「卡包/卡」是可生长的心智模型：R3 网页会话产品线直接叫"卡"，不需要发明新隐喻

**负面/约束**：

- 一次性大改名风险（187+ 触点）→ 分批实施，每批 `verify_project.py --test`
  七项门禁兜底，提交按意图细分
- 双端并行期需要协调词汇切换窗口 → STATUS 挂账同步，另一端合入后 rebase + 全量回归
