# ADR 索引

架构决策记录（Architecture Decision Record）。一篇 ADR 只回答一件事：**为什么这么做，以及现在必须怎么做**。
现行约束的全文在 `docs/conventions/` 与 `docs/specs/`，ADR 不重复规范正文。

## 命名与维护纪律

- **路径**：`docs/adr/<两位序号>-<业务面>/ADR-<三位编号>-<结论式标题>.md`（标题即结论，不写"关于…的探讨"）。
- **front-matter**：`name: butler-adr-<三位编号>`，与文件名编号一致；`level: must`；`description` 写清结论与
  `TRIGGER when …`。
- **编号不复用**：同一主题多轮演进写成一篇，新增裁决改写正文并升 `version`，不新开同主题编号。
- **一篇只讲当前**：不保留被取代的方案、旧编号、旧表名沿革；需要"为什么不这么做"时写进「备选（未采纳）」一节。
