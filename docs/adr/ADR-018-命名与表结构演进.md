# ADR-018 · 命名与表结构演进（术语 / 列名 / 表名 / 审计范式）

日期：2026-11-17（用户裁决）　状态：Accepted　影响域：全库术语 / accounts / 全表 DDL / 生成视图

> 本篇是 2026-11-17 同日五连裁决的合并归档（2026-11-20 整理）：
> 吸收原 **ADR-018/019/020/021/023/024** 六篇。命名与结构的**现行约束**
> 以 [06-SQL规范](../conventions/06-SQL规范.md) 为唯一入口，本文只记
> 裁决结论与演进脉络，不重复规范正文。

## 背景

同一个"AI 产品身份"概念先后叫 Provider → App → Platform，accounts 表从 v1
（id TEXT 复合主键 + provider/display_name）一路演进；同时裸表名难辨域、
执行域表缺审计三件。一天内连续五轮裁决，全部已落地并收编进规范。

## 现行裁决（合并视图）

1. **术语 = platform**：全库退役 provider/app，统一为**平台**（连接器家族、
   列 `platform_code`、路由 `/platforms`、`PlatformOut`）。保留不改：
   FastAPI/Typer 实例变量 `app`、AppBadge 组件名、第三方 LLM provider 描述。
   （原 ADR-018 定 app、ADR-019 修正为 platform）
2. **全库 DDL 范式**（收编 A4-01 §5）：每表代理键
   `id INTEGER PRIMARY KEY AUTOINCREMENT` + `created_at/updated_at` 审计必备 +
   禁用数据库关键字列名（`enabled` → `is_active`）。（原 ADR-019/020）
3. **账户域列名 code 化**：`account_key`→`account_code`、
   `display_name`→`account_name`；索引随列名。（原 ADR-020）
4. **表名 = 域缩写前缀 + 单数实体**：`acc_account` / `plat_platform` /
   `exe_claim` / `usage_*` / `health_state` / `vault_*` / `audit_log`；
   索引名随表名。（原 ADR-021；平台册落表后由 ADR-022 转入独立 platforms 域）
5. **显示名称列按业务命名**：账户 = `account_name`、平台 = `platform_name`，
   禁用 `display_name`/`name` 裸通用名。（原 ADR-023）
6. **执行域表 = exe_claim**（领取记录）：泛化 `exe_run` 改名，`run_id` 降为
   业务键（UNIQUE），补审计三件，幂等索引 `idx_exe_claim_idempotency`；
   core/契约的 Run 术语不变。（原 ADR-024）

## 迁移纪律

老库自迁移全部幂等（RENAME COLUMN / ALTER 纯增量 / 重建式搬迁），行数据
零丢失；schema 生成视图 `data/sql/` 随 `scripts/dump_db_schema.py` 刷新（勿手改）。

## 后果

- `/apps` → `/platforms`、账户契约字段改名均为破坏性变更（SDK 与 web 同步重生成）。
- 命名与结构约束的现行全文见 [06-SQL规范](../conventions/06-SQL规范.md)
  （其"裁决溯源"行指向本篇）。
