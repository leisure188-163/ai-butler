# ADR-012 · R4 网关独立进程八项架构裁决

- **状态**：Accepted
- **日期**：2026-11-14
- **决策者**：用户裁决（jason.zhuo）
- **关联**：A1-01 §4 L3、A1-02 §1、A2-01 §2（gateway.route）、A2-02 §3、
  A2-06（UsageSample.source）、docs/plans/02（立项任务书）、STATUS 决策（vault 审计底线）

## 背景

R3 收官后进入 R4（账户池/反代/规则引擎）。立项任务书（plans/02）列出 8 个
设计裁决点；mac 侧会话按既有锚点拟草案，用户逐条确认通过。上游推理通道
取证未做——本裁决只定架构面，实现细节随取证回收。

## 决策

1. **进程边界：gateway 进程内直调 butler_core**。gateway 是基础设施进程
   （非 UI 薄壳），比照 CLI/server 先例 import core——vault/凭据/计量端口
   进程内直调，热路径零额外一跳，vault 审计路径天然复用；配置与观测走
   server 契约（`gateway.route` 只读动作，A2-01）。
2. **主控通信形态：HTTP（localhost）**。「IPC/HTTP」二选一落 HTTP——server
   已是 FastAPI 常驻服务，配置拉取/观测上报复用契约 API，不发明新 IPC。
3. **凭据池：现用现取 + 短 TTL 缓存（按 provider kind 声明）**。CredentialPool
   端口先立，实现 = vault 现用现取（ADR-008 先例）、全审计；是否驻留等推理
   通道取证结论以 kind 扩展。凭据最小授权（A2-02 §5）不变。
4. **协议面鉴权：启动时生成随机 key + 本地配置文件（0600）**。兼容
   OpenAI/Anthropic 客户端 Bearer 习惯；绑定 127.0.0.1；不设用户体系
   （A1-02「默认不设 JWT」口径）。
5. **Router 最小集：固定优先级 + 故障转移**。M1 只做「按账户顺序 + 失败
   转移」；余额感知路由等推理通道取证（额度扣减语义）回收后增量。
6. **规则引擎：不做通用规则引擎**。「规则」= 声明式路由配置（模型 → 账户池
   静态映射），server 侧管理、网关只读。复杂引擎 YAGNI。
7. **Meter 口径：优先读上游响应 usage 字段，缺失记请求级计数**。兼容面响应
   自带 usage.tokens——R2 四家客户端通道逐调用双 UNSUPPORTED，网关面首次让
   逐调用 tokens 可得；缺失如实记次数/时长，不猜。入账 =
   `UsageSample(source="gateway")` 走既有 usage 通道。
8. **技术栈：Python + FastAPI + httpx（异步）**。与 server 同栈复用 core 与
   团队经验；「将来换 Go/Rust 只换此进程」由独立进程边界保证（A1-01）。

## 后果

**正面**：

- 八项一次定清，G1-G6 阶段（plans/02 §4）可开工；凭据池/计量复用既有
  底座（vault 审计、usage 通道、契约流水线），新增面最小
- Meter 让逐调用 tokens 首次可得（R2 遗留的 UNSUPPORTED 得到网关侧补齐）

**负面/约束**：

- gateway 直写 SQLite（usage 入账）引入跨进程写并发——须走台账语义
  （失败不影响转发主流程，A1-02 §6）+ WAL；锁冲突实测后如吃紧再改经
  server API 入账（裁决 1 的已知回退路径）
- 凭据池 TTL/驻留是临时形态，取证后可能 per-provider kind 化——pool 实现
  必须把「缓存策略」做成 kind 数据而非 per-app 分支（A2-02 §3 判据）
- 上游推理通道零取证：转发热路径的形状（流式/签名/机器头）未定，G5 前
  必须完成 plans/02 §3 取证；取证不全 = 不开工该 provider
