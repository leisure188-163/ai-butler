# ADR-032 · 同步只纳本机客户端，网址版走人工导入

- **状态**：Accepted
- **日期**：2026-11-19
- **决策者**：用户（本轮明确要求「同步平台时，web 端的不要导入，只导入客户端的应用，
  还有在界面上做一个功能，还有哪些没有导入，让用户手动去导入」）
- **关联**：ADR-021（平台册）/ ADR-022（platforms 域）/ ADR-031（平台名单列）

## 背景

启动同步与「同步平台」端点原来把**所有未退役连接器**都写进 `plat_platform`：
本机客户端（`kind=client`）与网页版（`kind=web`）一视同仁。平台页因此出现
用户根本不用的网页版平台（如 AgentRouter），名册被非本机应用占位；而网页版
没有本机客户端可探测，版本/图标恒为空，看起来像"坏了一半"的平台。

用户要的是名册等于「我这台机器上能用的应用」，网页版属于**可选**：
想用再导入，不想用就留在清单里。

## 决策

1. **自动同步（启动 / 热重载 / `POST /platforms/resync`）只纳两类**：
   - `manifest.kind == "client"` 的本机客户端；
   - 用户自建平台（`manifest.root_dir` 非空，创建即入册，不退回清单）。
2. **内置网页版不自动纳册**：出现在平台页「未导入的平台（N）」区块，
   按行提供「＋ 导入 xxx」按钮，点击 = 纳册 + 立即接入（`POST /platforms/{target}/adopt`）。
3. **策略性跳过 ≠ 退役**：`SyncPlatforms.execute(facts, known_codes=universe)` 的
   `known_codes` 传「未退役连接器 id 全集」；`deprecate_missing` 只把真正从
   连接器宇宙消失的行落 deprecated。否则每轮同步都会把网页版误标退役。
4. **未导入判据**（`GET /platforms/unimported`）：连接器存在且未退役、名册里没有
   活跃行；`account_ids` 如实带上名册外的既有账户（>0 = 导入后自动归位）。
5. **导入复用同一投影**：`adopt` 与同步共用 `platform_fact`，不另拼一套字段；
   未知/已退役连接器 422，不静默吞。

## 后果

- 平台页名册只剩本机应用；未导入是显式、可操作的清单，不再是"看不见的差异"。
- `sync_platforms` 用例多一个 `known_codes` 参数（可选，缺省 = facts 集合，
  保持老语义）；engine 适配器无需改动。
- 自定义平台创建接口（2026-11-18）继续即时入册：用户亲手建的不受本裁决影响。
- 若用户从未点导入，网页版的既有账户仍保留在账户域，只是平台不在名册——
  未导入清单会提示「名册外已有 N 个账户待归位」。

## 备选（未采纳）

- **只按 `kind` 过滤，不带连接器宇宙**：会把网页版每轮同步都误标 deprecated，
  历史行反复"退役又复活"，审计噪声大，否决。
- **网页版完全不可导入**：用户偶尔要用网页版连接器（如 AgentRouter 签到），
  一刀切等于砍能力，否决。
- **在 manifest 上加"是否自动纳册"开关**：每个连接器都要维护，且用户无法感知；
  由端按 `kind + 自定义` 统一裁决更简单，否决。
