# ADR-034 · 账户身份与编址（不透明主键 · source_key 唯一锚点 · 人工后缀）

日期：2026-11-18 ~ 11-20（用户裁决）　状态：Accepted（已执行）　影响域：accounts / vault / platforms / 契约

> 本篇是账户身份/编址主题的合并归档（2026-11-20 整理）：
> 吸收原 **ADR-025（编址用昵称，已废弃）/ ADR-030（别名绑定身份）/
> ADR-033（编址冻结·身份分离·凭据槽位·接入源）/ ADR-034 / ADR-035（人工后缀）** 五篇。
> 账户域现行规则正文以 [A2-04-accounts域](../specs/domain/A2-04-accounts域.md) 为准，
> 凭据槽位见 A4-01，接入源见 [A2-09-platforms域](../specs/domain/A2-09-platforms域.md)。

## 演进史（为什么换了四版方向）

| 版本 | 决策 | 结局 |
|---|---|---|
| 原 ADR-025（11-18） | `account_code` 用实际昵称（`doubao_cn:逍遥酒鬼`） | 昵称可变、重名撞索引，编址漂移——**废弃** |
| 原 ADR-033 §1（11-20） | 编址冻结：存量 id 保留、新写入不再用昵称 | 同日被下一版取代 |
| 原 ADR-034（11-20） | **彻底重置**：不透明主键 + source_key 唯一锚点（已执行） | 现行 |
| 原 ADR-035（11-20） | `account_code` 降为**可空人工后缀** | 现行 |

触发：真库同步后 `account_id` 混入平台名、昵称、`main` 占位与哈希；`RegisterAccount`
按拼接 id 幂等回放，导致同昵称两真人被静默并卡、同一人改昵称重复建卡；
`identity_json` 全 NULL，唯一性建立在展示名上而非真实人上。

## 现行裁决

### 1. account_id 不透明、不可变

- 新账户 id 固定 `acc_<8hex>`（uuid4 前 8 位查重），不从平台、昵称、编码推导。
- 存量 8 条 id 已于 2026-11-20 全部重发（方案 B，[`scripts/migrate_account_ids.py`](../../scripts/migrate_account_ids.py)，
  默认 dry-run、`--apply` 写库；依赖表 vault/exe/usage/audit/health/routes 全量改写，
  备份 `data/database/backup-account-reset-20261120/`，`integrity_check=ok`）。
- 旧复合 id 只保留在备份表与历史审计行，不再作为新写入。

### 2. source_key 是唯一身份锚点

- 独立列 `source_key TEXT NOT NULL DEFAULT ''`；唯一约束
  `UNIQUE(platform_code, source_key) WHERE source_key <> ''`（空串不占用）。
- 注册认回顺序：① source_key 命中 → 认回（改名改 code 都不新建）；
  ② 未命中 → 按 `(platform_code, account_code)` 查；③ code 命中但两边
  source_key 都非空且不同 → `AccountConflict` 显式拒绝，绝不静默复用；
  ④ 存量 `legacy:<code>` 占位键首次真实 dock 时就地吸收。
- 连接器回传口径：豆包 `sec_uid`、Qoder `user.id`、Trae `userId`（设备号）、
  WorkBuddy `account.uid`、AgentRouter `github_<user_id>`；取不到则留空，
  **禁止用昵称兜底匹配**。

### 3. 身份与来源分离

- `identity_json`（nickname/email/uid/org；source_key 已独立列不重复写入）；
  空身份落 NULL，不猜。
- `origin`：`connector`（本机客户端导入）/ `manual`（用户手建）；
  `last_seen_at` 为运营字段，不参与编址。

### 4. 显示层：account_name / alias / label

- **account_name 只描述账户自身**（客户端昵称/用户名/邮箱，取不到 = `未命名账户`），
  **禁止拼接平台名**；平台由列表分组/徽标表达。（原 ADR-035 决策 1）
- **alias 别名绑定真实身份**（原 ADR-030）：用户可编辑显示名，≤40 字，
  空串 = 清除；`PATCH /accounts/{id}` 只写 alias 一列，404/400 显式报错。
  纯显示层：不参与鉴权、调度、run target，避免"改名字把领取打到别的账户"。
- **显示标签 core 单源**（`account_label`，不落库，前端不自行拼装）：
  `alias > identity.nickname > account_name > account_code > account_id`。
  不保证唯一，重名消歧留后续。

### 5. account_code = 可空人工后缀（原 ADR-035）

- 同步账户一律留空（`''`）= 尚未关联登录账户；用户在账户详情手动填写/清空。
- 索引 `UNIQUE(platform_code, account_code) WHERE account_code <> ''`：
  空 code 可多条共存，非空平台内唯一。
- **永不参与连接器幂等**：同步幂等按 `(platform_code, source_key)` 认回，
  无 source_key 时用 `device_ref` 兜底。
- `UpdateAccount` 允许改 code；`account_id` 与 `platform_code` 冻结。
- 依赖 `(platform, code)` 的旧路径（裸平台发起 Run）改为：单账户自动选中，
  多账户必须显式传 `account_id`；`RunOut.account_code` 返回当前人工后缀。

### 6. 凭据槽位（原 ADR-033 §3）

- `vault_item` 主键 `(account_id, kind, slot)`，默认槽 `default`——存量秘密零迁移；
  非默认槽引用 `{account_id}:{kind}@{slot}`，轮换归档 `…@{slot}#{seq}`。
- `slot` 限 `[A-Za-z0-9_-]{1,24}`；`label` 只做显示。`CredentialPool.acquire`
  未指定槽时取默认槽；撤销支持整账户与单槽；删除账户 purge 全部槽与历史。

### 7. 接入源层（原 ADR-033 §4/§5）

- `platform_kind` 扩为 `web/client/relay/local/api`（语义 =「怎么连」）；
  `plat_platform` 新增 `base_url/protocol/models_json/origin`。
  `protocol ∈ {openai}`（11-20 修订：海外协议不接入）。
- `origin=user` 接入源不参与 `deprecate_missing` 启动退役；无 connector，
  不产 claim/usage 端口；账号走 `POST /accounts` 绑定，密钥走槽位端点。
- 写端点：`POST /accounts`（可带首份凭据）、`PATCH /accounts/{id}`、
  `POST/DELETE /accounts/{id}/credentials...`、`POST /platforms/providers`、
  `PATCH /platforms/{code}`（仅 origin=user）。

## 后果

- 账户唯一性由 `source_key` 承担：同一真人改名不再漂移，不同真人同昵称不再合并。
- 显示不再出现「Doubao CN · 逍遥酒鬼」类平台前缀；重复扫描不覆盖人工后缀。
- 手建 id `acc_xxxxxxxx` 不可读是冻结编址的代价，显示由 label 承担；
  label 不保证唯一。
- 回滚路径：停服 → 备份库覆盖 `data/database/butler.db`；旧 `vault_ref` 未删除。
