# 01 · 环境与命令（操作指南）

> 本文是"怎么做"，不是强制规范；红线见 [`../conventions/01-开发红线.md`](../conventions/01-开发红线.md)。

## 装依赖

```bash
uv sync && pnpm install      # Python: uv workspace；前端: pnpm
cp .env.example .env
```

## 常用命令

```bash
uv run uvicorn server.main:app --reload     # 主控 server（127.0.0.1）
uv run python -m butler_gateway             # 网关独立进程（R4，127.0.0.1:8100）
uv run butler cards list                     # CLI 卡列表（执行器/排障用，非主入口）
uv run butler records                        # 领取记录：最近 Run
uv run butler check                          # 体检：手动触发到期扫描
pnpm dev:web                                # 管理台 Vite
pnpm gen:sdk                                # 改 API 后重生成契约（忘跑 → verify FAIL）
cd apps/desktop && npm i && WEB_URL=http://localhost:5173 npm start   # Electron 壳
```

### 端口约定（2026-11-18 事故后固化，别自选端口）

| 角色 | 端口 | 说明 |
|---|---|---|
| 主控 server | **8000** | `apps/web/vite.config.ts` 的代理写死 `127.0.0.1:8000`；后端换端口 = 前端全页空数据（请求打到旧端口/僵死进程） |
| 网关 | 8100 | 独立进程 |
| 管理台 Vite | 5173 | 代理 `/api` → 8000 |

排障口径：页面出现「还没有平台」但库里明明有数据时，先 `curl -s --max-time 10
http://127.0.0.1:8000/api/v1/platforms` 验证后端；再 `curl -s
http://localhost:5173/api/v1/platforms` 验证代理链路。**不要同时起两个主控实例**
（两个调度器会对同一账户重复领取）。

> Windows 本机（home 目录 sqlite 伴生文件被虚拟化层拦截的机器）：server / 网关
> 改用 `scripts\start-server.ps1` / `scripts\start-gateway.ps1` 启动——两脚本
> 固化**同一** `BUTLER_DB`（项目内 `data\database\butler.db`）。网关与主控
> 必须同库：路由账户名册 / 凭据池 / 计量库都在库里，不同库 = 账户查不到、
> 计量互相不可见（split-brain）；未设 `BUTLER_DB` 时网关启动会告警。

### 旧库升级到分域 schema（2026-11-18 起）

2026-11-17/18 把 `accounts` / `runs` / `quota_ledger` / `usage_*` 等单数聚合表重构成
按域前缀的 `acct_account` / `exe_claim` / `usage_*` 分域表。仍指向旧库的机器启动后
**平台/账户全空**（代码只读新表），但库里数据还在旧表里。搬迁：

```bash
uv run python scripts/migrate_db_schema_v2.py --source data/database/butler.db        # 预览
uv run python scripts/migrate_db_schema_v2.py --source data/database/butler.db --write
# 会先备份 <库>.bak-<时间戳>，生成 <库>.migrated；确认服务已停再替换：
# Move-Item -Force data/database/butler.db.migrated data/database/butler.db
```

搬移口径：`accounts`→`acc_account`（`provider`→`platform_code`，`display_name`→
`account_name`，`id` 冒号后段→`account_code`）、`runs`→`exe_claim`、`audit`→`audit_log`、
`vault_items`→`vault_item`（凭据密文在本机凭据管理器，只搬元信息）、`quota_ledger`→
`usage_quota_ledger`、`usage_*` 同名加单数、`health_state` 原样。平台表 `plat_platform`
由启动时 manifest 同步自动生成，无需搬。
