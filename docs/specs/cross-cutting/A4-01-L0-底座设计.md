# A4-01 · L0 底座设计

> 凭据保险库 / 账号健康中心 / 事件总线与通知 / 审计。M0 交付，
> 是 L1~L7 全部能力的安全地基。

## 1. 凭据保险库（Vault）

**分层存储**（优先级从高到低）：

| 层 | 实现 | 适用 |
|---|---|---|
| OS Keychain | macOS Keychain / Windows Credential Manager（DPAPI） | 官方 Connector 凭据 |
| 加密库 | AES-GCM，主密钥来自 Keychain（Keychain 不可用时回退口令派生） | 无法进 Keychain 的文件型凭据（cookie 库等） |
| 内存 | 进程生命周期 | 运行时解密产物，绝不落盘 |

API（core 端口，ADR-003 起带槽位）：

```
vault.store(account_id, kind, secret, *, slot="default", label="", expires_at=None)
vault.load(account_id, kinds, *, slot="default") -> Secret[]  # 按 Connector 申报的最小集合解密注入
vault.rotate(account_id, kind, new, *, slot="default", expires_at=None)  # 换新 + 旧值进历史
vault.revoke(account_id, reason) -> int    # 整账户失效撤销：所有槽位旧值归档 + 删主引用 + 标记 revoked
vault.revoke_slot(account_id, kind, slot, *, reason) -> bool  # 单槽撤销（ADR-003）
vault.health() -> [CredentialHealth]       # 有效期/状态（含 revoked_at/slot/label），喂给健康中心
```

规则：
- **最小授权**：`load` 只解密调用方申报的 kinds（A2-02 §5）；默认只取 `default` 槽，
  要备用 key 必须显式传 slot（不隐式串用）
- **多槽位（ADR-003）**：同账户同 kind 可多份（`slot` 区分）；`vault_item` 唯一键 =
  `(account_id, kind, slot)`；引用默认槽保持旧形状 `{account}:{kind}`（存量秘密零迁移），
  非默认槽 `{account}:{kind}@{slot}`，轮换归档再追加 `#{seq}`；旧表迁移全部落 `default` 槽
- **失效撤销（ADR-015）**：健康判定 `invalid/expired` 时自动撤销该账户本地副本；
  旧值进 `#seq` 归档、主引用删除、`vault_item` 保留 `revoked_at/revoked_reason`；
  `load` 命中已撤销 → `CredentialRevoked`（仍按 NO_AUTH 处理）；
  **只动 butler 自己的库，不调用远程 signout、不删客户端凭据、不强制登出**；
  重新 `store` 清除撤销标记，修复重试必须先重新停靠读取客户端新凭据。
- 凭据明文只存在于内存与 Keychain；日志/事件/台账里一律 `[REDACTED]`（继承旧系统脱敏机制）
- 到期监控：每日 job 比对有效期，产出 CREDENTIAL_EXPIRING / EXPIRED 事件；
  已撤销副本不再参与到期事件

## 2. 账号健康中心

```
AccountHealth = {level, evidence, checked_at}
level: healthy | expiring | expired | invalid | risk
```

- 探测器 = 特殊的 Run（kind=health.check），走 Connector 的 status 探测声明
- **严重度映射（ADR-015）**：`healthy=silent`、`expiring=badge`、
  `expired / invalid / risk=push`——硬失效与凭据被拒是阻塞性事实，用户不打开
  界面也必须知道
- 分级驱动 UI：healthy 静默；expiring 徽标提醒；expired/invalid 进"待处理"
  并带 repair_hint（`action_id=relogin` → "在客户端退出并重新登录后重试"；
  缺凭据/需重扫 → "重新扫描"）
- **失效自动撤销本地副本（ADR-015）**：有 NO_AUTH 连败（含由此判出的
  `invalid/risk`）或凭据 `expired` 时调用 `vault.revoke`；`risk` 若来自其它
  信号不触发；撤销只清 butler 库，客户端会话不受影响；重试前必须先重新停靠，
  `CredentialOut` 带 `revoked/revoked_at/revoked_reason`
- 封号风险信号（连续 NO_AUTH、异常错误码簇）→ level=risk，severity=push 通知

## 3. 事件总线 + 通知中心

```
EventBus（进程内 asyncio）
  ├─ subscribers: 台账写入 / 统计聚合 / 通知中心 / 规则引擎(L3)
  └─ 事件 schema: {type, ts, account_id?, severity, payload}
```

通知渠道（适配器，可插拔）：

| 渠道 | 默认 | 说明 |
|---|---|---|
| 应用内 | on | 待处理列表 + 托盘角标 |
| 系统通知 | on（仅 push 级） | 桌面通知；macOS `osascript` / Linux `notify-send`；测试/CLI 默认关（`BUTLER_SYSTEM_NOTIFY`） |
| Webhook | off | 通用出站 POST（飞书/钉钉/Server酱经配置模板适配） |
| 邮件 | off | 每日摘要形态，不做逐条推送 |

规则：
- 通知中心是 Event 的**唯一消费者出口**；其他订阅者不许直接通知
- severity: silent / badge / push 三级，用户可在设置里按事件类型覆盖
- 登录态失效（`ACCOUNT_HEALTH_CHANGED` 且 level=invalid/expired）必须走 push：
  系统通知 + 应用内待办；同一级别只在**变化时**发一次（ADR-015）
- 系统通知渠道必须**如实投递**：平台无命令时显式失败并记日志，不假装送达
  （Windows toast 未接入前按此口径处理）
- 通知必须可追溯到 Run/Event id（点击通知 → 对应证据页）

## 4. 审计（Audit）

- append-only 表：`{ts, actor, account_id, credential_ref(哈希非明文), action, outcome}`
- 触发点：凭据存取/轮换、所有写操作（claim/import/route 变更）、连接器安装与升级、
  **凭据池每次 acquire**（含缓存命中——actor=gateway-pool，hit/miss/error 分记，
  ADR-012 裁决 3；miss 路径叠加 vault.load 自带的 vault 级审计）
- 反代上线（R4）前审计必须就位——这是 L3 的安全底线，不是可选件
- 提供导出（JSON）用于排障；保留策略默认 90 天

## 5. 数据层约定

- SQLite(WAL) 单库；表按域分置（**现状 11 张表**，分域生成视图 `data/sql/*.sql`，platforms 域 = ADR-001）：
  acc_account / exe_claim / plat_platform / usage_snapshot / usage_aggregate /
  usage_quota_ledger / usage_sample / health_state / vault_item / vault_history /
  audit_log——凭据元数据与健康态同库；events 走进程内总线不落库
- **表名纪律（2026-11-17 用户裁决，ADR-018）**：表名 = 域缩写前缀 + 单数实体
  （acc_/exe_/usage_/health_/vault_/audit_），禁裸实体名——业务扩展后可辨域、
  易管理；历史改名由 001_initial.sql squash 收编（ADR-018）
- **全库 DDL 约定（2026-11-17 用户裁决，ADR-018）**：每表
  `id INTEGER PRIMARY KEY AUTOINCREMENT` 代理键必备；统一审计列
  `created_at TEXT NOT NULL` + `updated_at TEXT NOT NULL` 必备；业务规范 id
  （如 acc_account 的 `{platform}:{account_code}`）落 UNIQUE 列不动主键；
  禁用数据库关键字作列名（`enabled`→`is_active`）。DDL 权威单源 =
  `butler_engine/db/migrations/*.sql` 编号迁移文件（**ADR-018 起**，取代旧
  「域适配器 `_SCHEMA` 常量」裁决）；`data/sql/*.sql` = 迁移链基线快照
  （DBA 审查入口，勿手改）
- 时序独立表（`usage_sample`）与按天分区 = **R 系列后续方向**（量级未到阈值；
  现行用量 = 上列三表：快照/汇总 `INSERT OR REPLACE`（id 幂等）、额度流水
  `INSERT OR IGNORE`（(account_id, record_id) 幂等去重），不混业务查询；
  分区落地时按 ADR-018 新增编号迁移文件）
- 台账写入失败 → 事件总线记 error 并降级重试，**不影响业务主流程**（继承旧系统 ingest 语义）
- Repository 接口隔离：SQL 只存在于 packages/engine 适配器层（butler_engine）
- **schema 演进**（2026-11-12 增补；**ADR-018 全面改写**）：~~启动时按
  `PRAGMA user_version` 顺序执行迁移~~ → **migration-first**：改表 = 新增
  `NNN_描述.sql` 迁移文件，版本表 `db_migration`（version/name/checksum/applied_at）
  由迁移器自举记账，`open_db`/lifespan 幂等追跑；❌ 不用 `PRAGMA user_version`
  （本条预埋被 ADR-018 显式取代：多服务共享库时版本必须可见可查）；
  历史自迁移已 squash 为 001_initial.sql
- **全库 schema 视图**（2026-11-15 增补；ADR-018 重定位）：`data/sql/<域>.sql` 由
  `scripts/dump_db_schema.py` 生成（临时库跑迁移链 → dump `sqlite_master`，
  按业务域分文件）；定位 = **迁移链基线快照 + DBA 审查入口**，改表后须重跑
  导出并随批提交（`--check` 校验漂移）；新表先在脚本 `_SECTIONS` 登记分节
  （未登记显式报错退出）
- **数据根**（2026-11-11 补，M0 遗留修正；2026-11-14 定名 butler；
  **2026-11-16 修订**：Windows 本机文件虚拟化层拦截一切 sqlite 伴生文件（-wal/-shm/-journal
  创建即被回收，四次 disk I/O error 实证）并锁死平台标准数据根的库文件写回——经用户裁决
  **数据根迁至项目内 `<repo>\data\database\butler.db`**（D 盘可写），`BUTLER_DB` 覆盖
  由启动脚本 `scripts/start-server.ps1` 固化；本机 SQLite 全域
  `journal_mode=OFF` 弃伴生文件（**代价如实登记**：OFF 没有回滚日志，崩溃/掉电时
  可能**损坏库文件本身**——不是"丢最后一条写"，动作幂等只兜住重复执行、兜不住库
  损坏；对策 = 定期备份，机制待落地，见 STATUS 剩余挂账）。原「禁止
  CWD 相对默认」条款的适用前提（平台标准数据根可用）在本机不再成立——运行数据仍不进
  git（`data/database/` 与 `data/doubao_identity.json` gitignore 排除），schema 生成视图
  迁 `data/sql/` 入库版本化）：库统一落平台标准
  用户数据目录 `butler/`——macOS `~/Library/Application Support`、Windows `%APPDATA%`、
  Linux `$XDG_DATA_HOME`（**Windows 本机例外见上方 2026-11-16 修订**；
  **2026-11-19 全平台统一**：经用户裁决，mac/Linux 也一律用项目内
  `<repo>/data/database/butler.db`，平台默认根不再作运行库，由
  `scripts/start-server.sh` 固化 `BUTLER_DB`；口径单源见
  `docs/conventions/00-项目配置.md` 的 `{data-root}`）；`BUTLER_DB` 环境变量整体覆盖（测试/便携模式）。
  **禁止 CWD 相对默认**——否则运行数据混进代码仓库（曾发生）；旧标识目录
  `ai-marina/marina.db` 与 CWD 旧库首次运行自动迁入数据根（`bridge.default_db_path()`，
  迁移源优先级与幂等性见 A1-03 §7）。网关鉴权 key 文件同落数据根
  （`gateway-auth-key`；POSIX `0600`，**Windows 走 `icacls` 撤销继承 + 只授权
  当前账户**——NTFS 无 POSIX 权限位，`chmod` 给不出 0600，ADR-014；
  `BUTLER_GATEWAY_KEY_FILE` 覆盖）
