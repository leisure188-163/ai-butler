# A2-01 · 领域模型与动作模型

> core 的实体、结果词汇、动作/事件模型。本文是 `packages/core` 的实现蓝图，
> 依赖方向：本文定义的都在 core 内闭环，端与适配器只消费。

## 1. 实体（聚合根：Account）

```
Workspace（本机工作区, 单实例）
 └─ Provider（AI 产品: trae_cn / qoder / doubao_cn / workbuddy_cn / …）
     └─ Account（聚合根）
         ├─ identity: 展示名 / 归属客户端 / 状态分级
         ├─ Credential[]  凭据: kind(ss_aes/cookie/oauth/api-key) / 密文 / 有效期 / 轮换历史
         ├─ Entitlement   权益: 余额 / 连签 / 上次领取窗口
         ├─ UsageSample[] 用量: tokens_in/out / model / ts / source(client|gateway|api)
         └─ Session[]     会话: 存储位置 / 可迁移级别(local|inject|server)
```

规则：
- Account 是唯一的业务标识锚点——所有 Run / Event / Sample 都挂 account_id
- Provider 是 Connector 的产品级身份，**不出现在 UI 导航**（下沉为实现细节）
- 多账户：同 Provider 下 N 个 Account 并行，互不共享凭据

## 2. 结果词汇（单源，`domain/results.py`）

```python
class Status(StrEnum):
    CLAIMED = "CLAIMED"        # 本次执行完成领取
    ALREADY = "ALREADY"        # 本窗口已领过（幂等命中）
    NO_AUTH = "NO_AUTH"        # 凭据缺失/失效
    EXPIRED = "EXPIRED"        # 登录态过期
    FAILED  = "FAILED"         # 执行失败
    PENDING = "PENDING"        # 服务端判定暂不符合条件（如实上报，不算失败）
    SKIPPED = "SKIPPED"        # 计划内跳过（如通道不可用）

@dataclass(frozen=True)
class ResultKind:             # 分类谓词：端上渲染只消费这些
    is_pass: bool
    is_attention: bool        # 需要用户处理（进"待处理"）
    is_fail: bool
```

规则：
- 字面量与旧系统方言对齐（验收 oracle 零损耗）；`from_engine(text)` 是唯一翻译入口
- 端上禁止出现 `if status in [...]` 式语义映射表（verify + 人工评审把关）
- 每个结果可携带 `repair_hint`（人话原因 + 修复动作 id），支撑"待处理 → 一键修复"

## 3. 动作模型（Action / Run）

```
Action = (kind, target, params)
  kind: provision.run | provision.claim | usage.collect | usage.query
      | session.export | session.import | health.check | gateway.route(只读配置)

Run = 一次 Action 的执行记录
  id / action / account_id / idempotency_key / started_at / budget
  → Result(status, kind, evidence[], repair_hint?)
```

规则：
- **幂等键** = (kind, account_id, 签到窗口)——重复触发不会重复领取（继承旧系统已验证语义）
- **时间预算**（budget）是 Run 的一等属性：超预算立即停止并如实上报，不静默截断
- evidence：结构化证据（原始错误码/响应摘要，脱敏后），折叠展示用
- `provision.run` 的硬承诺：`dry_run=True` 只报告不领取；Connector 不支持 → 用例层拒绝，**绝不静默降级**

## 4. 触发器（Trigger）

| 类型 | 来源 | 说明 |
|---|---|---|
| cron | 进程内调度器 | 默认通道；系统级定时任务（schtasks/launchd/cron）作为**兜底触发器**注册 |
| event | 事件总线 | 如 CredentialExpired → 触发 health.check |
| threshold | 阈值 watcher | 如 QuotaLow → 触发通知/规则引擎 |

规则：触发器只负责"发起 Run"，所有业务判断在 core 用例层。

## 5. 事件（Event）

```python
# 事件 schema: {type, ts, account_id?, severity, payload}
RUN_FINISHED        # Run 终态（含 status/kind）——通知、台账、统计的统一入口
CREDENTIAL_EXPIRING # 凭据 N 天内到期
CREDENTIAL_EXPIRED
QUOTA_LOW           # 额度低于阈值（L2 产出）
PROTOCOL_CHANGED    # Connector 探测到上游协议变化（L7 协议守护）
ACCOUNT_HEALTH_CHANGED
```

规则：事件是 L0 通知中心唯一输入；severity 决定打扰级别（silent / badge / push）。
**全部成功 = silent**，只有 `is_attention` 结果才产生可见通知。

## 6. 端口（Port）与能力申报

```python
class ProvisionPort(Protocol):
    def capabilities(self) -> Capabilities: ...   # 如实申报: dry_run / 多账户 / 幂等窗口
    def run(self, req: ProvisionRequest) -> RunResult: ...  # 结构化结果, 不返回退出码
```

规则（继承 cross-platform-arch 六边形约束）：
- 端口签名即能力边界：签名里没有的形参 → 申报不支持 → 用例层拒绝
- 适配器不做语义决策、不解析日志文本、不维护结果映射表
