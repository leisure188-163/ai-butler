> A1-04 的实现细案 v1（2026-11-13）。承重裁决已批（A1-04 §2/§3/§4）：直读
> cookie、Chrome·mac+Win 首批。本文回收 A1-04 §8 待裁清单中的实现面裁决
> （§8.2 钥匙读取形态、§8.5 两态导入语义），并定 `browser_cookie` 凭据 kind、
> capture 通道声明形状与 health.check 探针的端口/词汇映射。
> 纪律：kind 收敛原则（A2-02 §3）全程适用——捕获与探针都是**共享运行时**，

## 1. 凭据 kind：`browser_cookie`

开放词汇表新成员（core 不封枚举，`domain/vault.py` 口径照旧）。

**信封形状**（dock 组装、vault 加密存放、loader 解出字段）：

```json
{"browser": "chrome", "domain": "chatgpt.com",
 "cookies": [{"name": "...", "value": "...", "expires_at": "2030-01-01T00:00:00+00:00"}]}
```

- 只存申报名单内的 cookie（数据最小化；要更多 → 先改 PROTOCOL 与名单声明）
- 信封里是**明文 cookie 值**——只在内存存在，入库走 vault 加密（A1-04 §3
  ❌ 条款：不落盘、不进日志、不进 evidence）
- **凭据有效期 = 名单内各 cookie `expires_at` 最早者**（A1-04 §5）；
  全是会话 cookie（expires_utc=0）→ None（无到期，真失效由探针如实报）

**解锁链**（unlock.py 单源，双平台显式分派）：

| | macOS | Windows |
|---|---|---|
| 钥匙 | Keychain「Chrome Safe Storage」→ PBKDF2-HMAC-SHA1(saltysalt, 1003, 16B) | Local State `os_crypt.encrypted_key` → 剥 DPAPI 前缀 → CryptUnprotectData（32B） |
| 密文 | `v10` + **单条 AES-128-CBC 链**（A1-04 §4.1-8，2026-11-14 定论）：明文 = `sha256(host_key)[:32] ‖ PKCS7(value)`，IV = 16 空格——头 32B = 域绑定完整性标签，capture 层落地校验（unlock.py 前缀切法输出 = 载荷 = 真值） | `v10` + nonce(12) + AES-256-GCM；**v20 = 应用绑定加密显式落榜**（2026-11-13 Windows 真机：可读 profile 124 条全量 v20，Chrome 127+ App-Bound——解密需冒充 Chrome 进程，属对抗绕过，不做，A2-03 §7.7） |

mac 链与 qoder safeStorage 同构（unlock.py 常量复用），A1-04 §4.1 本机取证
全通；结构定论（2026-11-14，A1-04 §4.1-8）：单条 CBC 链、头 32B = sha256
(host_key) 域绑定标签、整链重放 528/528 闭环，capture 层落地完整性校验；
win 链 2026-11-13 Windows 真机验收（§7.3）：DPAPI 钥匙腿实解（209B→32B）+
GCM 腿真钥匙 roundtrip 通过；真实 cookie 腿因 v20 应用绑定加密不可解
（显式落榜，不做对抗解密）。

**字段装配**：`load_browser_cookie` → `{"cookie": "n1=v1; n2=v2"}`；
`fill_auth_headers` 按 kind 分支——`browser_cookie` → `Cookie` 头
（缺字段 = TemplateFieldMissing，红线 5 照旧）。

## 2. capture 通道：声明式 `session.import`

与 provision 五段式并列的第二种声明形状——**捕获无 status/claim/window 语义**
（A1-04 §6：无领取概念，不发明），只有 auth 段：

```yaml
# declarative/session.import.yaml
auth:
  kind: browser_cookie
  browser: chrome              # 可枚举 kind（首批唯一值）
  domain: chatgpt.com          # registrable domain（host 精确或点后缀匹配）
  cookies:                     # 必需名单：全在才算登录（判据单源）
    - __Secure-next-auth.session-token.0
    - __Secure-next-auth.session-token.1
  storage:                     # cookie 库候选（平台宏 + glob 文件，复用 paths 机制；
                               #  新旧布局并配——Chrome ≥96 库在 <profile>/Network/）
    - "~/Library/Application Support/Google/Chrome/*/Cookies"
    - "~/Library/Application Support/Google/Chrome/*/Network/Cookies"
    - "%LOCALAPPDATA%/Google/Chrome/User Data/*/Cookies"
    - "%LOCALAPPDATA%/Google/Chrome/User Data/*/Network/Cookies"
```

**捕获流程**（connectors/browser.py，与 dockio 平行读本机状态）：

1. 候选库展开（storage_override 可注入，测试同 dock 先例）；
2. 逐库**字节拷贝到临时文件**（try/finally 用后即删，拷贝的是密文库，取证
   纪律照 M1）；活动库被浏览器锁死（2026-11-13 Windows 真 Chrome 实证：
   连 Python open 都进不去）→ SQLite ``immutable=1`` 只读直开兜底（零锁零写），
   再不成如实出账「关闭浏览器后重扫」；
3. `SELECT name, encrypted_value, value, expires_utc FROM cookies` 按
   host（`domain` 精确或 `.<domain>` 后缀）× 名单过滤；
4. 逐条解密（§1 链）；legacy 明文 `value` 列非空且无密文 → 原样收（如实）；
5. **首个凑齐必需名单的 profile 胜出**（路径排序稳定）；单库锁死/解不开 =
   记首个原因**换下一个 profile 继续**（2026-11-13 真机取证：活动 Default
   锁死不影响可读 Profile 1），全落空有事故报事故、无事故按未登录；
   多 profile 同登 = 静默取首个——M1 单账户契约的既定边界，多账户导入
   随 M2 卡册重开。

**两态导入语义**（A1-04 §8.5 回收；本机 ChatGPT/Claude 是天然试金石）：

| 态 | 判定 | 处置 |
|---|---|---|
| 未登录 | 无任何 profile 凑齐必需名单 | `DockOutcome.issues` 如实落榜：「未登录（Chrome 无 {domain} 会话 cookie）——浏览器登录后重扫」；**不注册账号** |
| cookie 在但过期 | 名单凑齐，最早 expires 已过 | **照常出卡**：注册 + 入库（expires_at 为过去值）→ 到期扫描/健康分级如实示 EXPIRED |

其余事故态：库不存在 → issues（装 Chrome 提示）；钥匙拒绝/解密失败 →
issues（mac 指向 Keychain 授权，与 qoder mac 分支文案分流同款）；活动库
锁死 → issues（指「关闭浏览器后重扫」）；v20 应用绑定加密 → issues
（显式落榜，不误导重扫——§7.7）。

**钥匙读取形态**（A1-04 §8.2 回收）：**`security` CLI**（qoder mac 分支同款，
`macos_safe_storage_password(service)` 已参数化，复用）；Security.framework
API 注入不做——零新依赖 + 子进程替身注入先例齐备。测试经 `key_provider=` /
`dpapi=` 参数注入（unlock.py 既有模式）。

## 3. 探针通道：声明式 `health.check`

**首个主动 health.check 端口**（此前 ActionKind 词表挂着无实现）。声明形状：

```yaml
# declarative/health.check.yaml
auth:
  kind: browser_cookie
probe:
  request: {method: GET, url: "https://chatgpt.com/api/auth/session"}
  ok_status: 200                # HTTP 200 = 会话有效
codes:                          # HTTP status → Status 字面量（装载期注册方言，ADR-004 单源）
  "401": "EXPIRED"
  "403": "NO_AUTH"
```

**端口形状**：`DeclarativeHealthPort`（实现 core `ProvisionPort` 协议结构——
capabilities() + run(ProvisionRequest)，复用既有路由/台账/事件机制，core 零改动）：

- `run` 按 `req.kind` 分派：非 `health.check` 一律如实拒绝
  （FAILED + evidence「本连接器不支持 {kind}」——网页通道无领取概念）；
- 探针流：解锁 `browser_cookie` → Cookie 头 → 按 deadline 预算发请求 →
  HTTP status 判定；**evidence 附响应摘要**（body 类型/错误码字段，截断脱敏）；
- 未知 HTTP status（如 500/区域阻断形状）→ `UnknownEngineCode` →
  ExecuteAction 统一 FAILED + PROTOCOL_CHANGED 事件（协议变更探测照旧）。

**七词映射裁决**（本 spec 新裁定，A2-01 §2 词表不新增）：

| 探针结果 | Status | 依据 |
|---|---|---|
| 会话有效（HTTP ok_status） | `ALREADY` | 「期望态已达成、无需动作」的幂等语义移植到健康语境：healthy = silent（A2-01 §5 全部成功不打扰）✓；台账行 = action health.check + ALREADY，如实不误导 |
| 名单内声明映射 | `EXPIRED` / `NO_AUTH` | 每家 PROTOCOL 定（ChatGPT：401→EXPIRED、403→NO_AUTH 挑战） |
| 网络不可达 | `FAILED` | TransportError 如实（探针发不出去 ≠ 会话失效） |

- `NO_AUTH`/`EXPIRED` → `RepairHint(action_id="dock")`（修复 = 重新导入，
  复用 dock 动作 id；文案 core 单源 decl.py）
- **到期提醒免费获得**：import 存 expires_at → ScanCredentialExpiry 每日扫
  → CREDENTIAL_EXPIRING/EXPIRED 既有事件链，零新代码

**定时体检轮询已落地（R3-2，2026-11-13）**：engine `start_health_scans()` 每日
job（IntervalJob 语义：启动即补扫一轮），`_daily_health` 对号册全账号逐个
`execute(HEALTH_CHECK)`——Run 照常落台账，EXPIRED/NO_AUTH 的 RepairHint 随 Run
出账，连败升级走 AssessAccountHealth 既有反馈回路（体检是回路的输入）。
轮询名册 = 探针名册：`register_health_ports` 挂载即登记，「有端口」与「该每日
轮询」是同一份事实；无 provider 或未挂端口的账号跳过（job 不为它们报错）。
单账号异常落 WARNING 不打断整轮（ExecuteAction 对适配器意外异常落账后原样上抛，
job 侧兜住）。server 组合层默认开启，`KABAO_SCHEDULE=0` 可整体关闭。

## 5. 红线映射

- 红线 2（端零映射）：探针/导入结论全部是 core 出产 Status/signal/repair_hint；
  UI 只按 capabilities 是否含 health.check 决定按钮渲染（能力申报，非语义映射）
- 红线 4（契约先行）：RunIn.kind 进 OpenAPI → SDK 派生，零手写字段
- 红线 5（显式报错）：未登录/钥匙拒绝/region 阻断/未知码/动词拒绝全部如实出账
- 红线 6（token 唯一来源）：本批 web 端零新样式
- 取证纪律（A1-04 §7）：cookie 值/密钥不落盘不进日志；临时拷贝用后即删；
  只读，对浏览器零写操作；遇 challenge 如实 NO_AUTH，无对抗绕过

## 6. 测试策略（A2-02 §8 四条全适用）

- 捕获：假 profile 目录 + 真 cryptography 造库（CBC/GCM 双分支各造密文），
  key_provider/dpapi 注入替身；两态语义断言；临时文件删除断言
- 探针：FakeTransport 剧本（200→ALREADY、401→EXPIRED、403→NO_AUTH、
  未知码→UnknownEngineCode、动词拒绝、evidence 摘要）
- 装载：两家新连接器 manifest/YAML 被注册表拾起（CI ubuntu 照跑，平台
  分支单测不触发真系统调用）
- 真机验收 = 行为对照：ChatGPT 过期卡 + Claude 未登录落榜（本机两天然样本）；
  Windows 批（2026-11-13）：现代布局发现 / 锁死兜底 / v20 显式落榜 /
  DPAPI 钥匙腿 + GCM 腿真钥匙闭环——全部回归测试钉住（锁死×2、垃圾库换

## 7. 已知局限与挂账（实现后回填 STATUS）

1. ChatGPT 探针端点未登录态形状**本机不可取证**（直连不通、无代理）——
   端点按 next-auth 惯例声明，PROTOCOL 标注「待登录态补证」
2. Claude 区域 403（region_unavailable，2026-11-13 本机取证）：受限网络探针
   恒 NO_AUTH——真凭证判级靠 expires_at 元数据，探针价值在可达网络
3. Windows cookie 解密分支真机验收 **2026-11-13 完成**（本批）：现代布局
   双候选补齐、锁死兜底 + 逐 profile 隔离落地、DPAPI 钥匙腿（真
   CryptUnprotectData 209B→32B）+ GCM 腿（真钥匙 roundtrip）真机 PASS；
   真实 cookie 腿本机不可取证——可读 profile 全量 v20（见 7）
4. 多 profile 同登静默取首个（M1 单账户边界）；M2 卡册重开
5. Claude cookie 名单待登录态环境补证（本机无登录态，A1-04 §8.3 既挂）
6. 探针定时轮询已落地（R3-2）；代理感知未做（探针走系统代理）
7. **Windows Chrome 127+ 应用绑定加密（v20，2026-11-13 真机取证定性）**：
   可读 profile 的 124 条 cookie 全量 v20（App-Bound）——解密需冒充 Chrome
   进程调 IElevator COM，属对抗绕过，本通道不做（A1-04 §7 纪律）；
   Windows 新版 Chrome 的网页会话本机捕获如实落榜（显式形状错误
   `CookieShapeError` 已落地，不误导重扫），待浏览器侧变化再评估
