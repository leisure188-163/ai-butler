# A1-03 · 命名与语言标准

> 状态：**生效 v2.0（2026-11-14）**
> 本文件是**命名 / 业务语言 / UI 文案的唯一事实来源**：全部文档与代码以本表为准。
> 架构不变（一核多端、ADR-001/002 照旧）；历史更名裁决已随文档清理删除，
> 现行命名以本文件 §6 当前值为准。

## 1. 定位

- **定位一句话**：AI 智能助手管家（工程标识 Butler）——本地优先的智能助手管家：
  把各家 AI 助手的账户、余额额度、有效期收进一处，自动领取、到期提醒、流量
  一目了然，替你打理。
- 产品定位 / 能力分层 / 里程碑的完整出处见
  [A1-01 产品定位与能力全景](A1-01-产品定位与能力全景.md)。
- 目标用户：同时用 2 个以上 AI 工具的重度用户。
- 策略：**广度优先**（通用 AI 助手管家）——先横向覆盖更多 AI 产品（R3 网页会话线），
  深度调度（网关 / 会话迁移）靠后。

## 2. 业务通用语言准则（四条铁律，强制）

1. **圈外秒懂**——用户可见词只用大众白话或行业通用词；
2. **一个概念一个词**——中英一一对应，禁同义漂移；
3. **隐喻只能用大众心智模型**（管家 / 账户 / 应用），禁止内部隐喻体系；
4. **工程术语只留代码层**（端口 / 适配器 / 六边形），绝不外溢到 UI 文案。

## 3. 两层词汇原则 + 核心词表 v2

**两层词汇**：

- **协议词汇（保留不翻译）**：Status 七字面量 `CLAIMED / ALREADY / FAILED / NO_AUTH / PENDING /
  EXPIRED / SKIPPED`——ADR-004 方言、与旧系统 oracle 对齐，是 **API 层契约**。
- **产品词汇（全量白话）**：UI 中文映射（已领取 / 今日已领 / 失败 / 需要登录 / 待处理 / 已过期 /
  已跳过）。UI 只消费 signal 分类 + 协议字面量的中文映射，不直出协议词。

**核心词表 v2**（词条 = 中文 + 英文 + 标准定义 + 禁用同义词）：

| 中文 | 英文 | 定义（标准定义） | 禁用同义词 |
|---|---|---|---|
| 智能助手管家 | Butler | 产品名本体：替用户打理各家 AI 助手的管家 | — |
| 账户 | Account | 一个 AI 服务里的一个身份 | 账号、泊位 |
| 应用 | App | 一家 AI 产品（Qoder/Trae/ChatGPT…）；数据层字段名 = `app`（2026-11-17 用户裁决） | Provider（→App） |
| 仪表盘 | Dashboard | 默认首页：今日一句话结论 + 待办栏 + 速览 | 首页 |
| 流量 | Traffic | 余额/额度/用量采集与耗尽预测的页名 | 额度雷达、用量（页名级） |
| 日志 | Logs | 动作台账（runs）的用户可见名 | 记录（页名级） |
| 导入 | Import | 从本机客户端/浏览器读取凭据建立账户 | 停靠 |
| 领取 | Claim | 签到/领积分/领权益的统一动作 | 补给 |
| 余额/额度 | Balance/Quota | 还剩多少（积分/次数/Token） | — |
| 用量 | Usage | 已消耗量（**域内数据语境保留**：用量流水/已用量） | 页名级禁用（→流量） |
| 体检 | Health check | 凭据/账户健康评估与到期检查 | 扫海 |
| 提醒 | Alert | 异常/到期/待处理通知 | 灯塔 |
| 时间表 | Schedule | 自动领取班次 | 潮汐表 |

**退役禁用词**：卡、卡包、泊位、账号（→账户）、首页（页名级→仪表盘）、provider（→app，2026-11-17 用户裁决；第三方 LLM provider 等外部机制描述除外）、
记录（页名级→日志）、额度雷达（语系）、航海系全词（船/港口/灯塔/潮汐/舱位/扫海…）。

**执行口径**：

- 页名级（导航项/页标题/页副题）必须换新词；域内数据语境酌情保留（如「用量流水」）。
- 连接器原始返回文本不算 UI 文案（数据直渲染纪律不变，不扫）。
- 工程层标识（包名/命令/env/db 文件名/存储键）不属文案，按 §6 命名标准走。

**适用边界**：用户可见面（UI 文案 / CLI 命令与帮助 / 文档正文 / README）。
**不适用**：协议字面量、领域实体名（Account / Action / Run / Event）、
[A0-01 旧系统资产](../legacy/A0-01-旧系统知识资产.md)（描述前代项目）、git 历史。

## 4. 信息架构（2026-11-14 六页 IA，[ADR-010](../../adr/ADR-010-六页信息架构.md)）

- **左侧边栏导航 · 六页平铺**：**仪表盘（默认）/ 应用 / 账户 / 流量 / 日志 / 设置**。
  页名按词表 v2；顶栏单行「AI 智能助手管家」+ 拉丁标 Butler；
  ≤900px 顶条同样显示主名。
- **仪表盘** = 一屏回答「今天有事要做吗」：今日一句话结论 + 待办栏三节 +
  速览四行；提醒角标挂「仪表盘」项（待处理 + 非正常账户 + 临期凭据，
  条目数不去重——计数口径零变化）。
- **应用** = 六列表册（能力/时间表/账户数/状态汇总）+ 导入入口；
  **账户** = 9 列矩阵工作台 + 领取/体检；**流量** = 余额/流水/耗尽预测；
  **日志** = 操作台账；**设置** = 通用/提醒规则/关于。
- 页面状态走 hash 直链：`#/dashboard`、`#/apps`、`#/accounts`、`#/traffic`、
  `#/logs`、`#/settings`；**重定向表 v2**（7 条）见
  [A3-01 v2 §3](../application/A3-01-信息架构与核心页面.md)。
- 详细页面规格见 [A3-01 v2](../application/A3-01-信息架构与核心页面.md)。

## 7. 数据自动迁移（运行时行为）

- **db 腿**：首次运行时新数据目录无 `butler.db` 且历史数据源存在
  → 自动搬移（连同 `-wal` / `-shm`）并改名 `butler.db`。旧源链两条按优先级
  （**2026-11-16 收窄**：原两条 CWD 源移除——每次构造 engine 都会扫 CWD
  并把同名文件搬走，属隐式破坏性操作，与「禁止 CWD 相对默认」相悖；存量
  机器早已迁完，确有 CWD 旧库先手工移入品牌目录）：
  ① 数据根/`kabao`/`kabao.db` ② 数据根/`ai-marina`/`marina.db`；
  显式指定 `BUTLER_DB` 时以环境变量优先、**不做搬移**。
- **localStorage 腿**（web 端）：读 `butler.settings.v1`，缺失则读
  `kabao.settings.v1` 并写入新键；旧键保留不删。
- **安全**：历史文件**保留不删**（天然备份）；迁移幂等（新库/新键已存在即跳过）；
  db 迁移动作写审计日志。迁移源优先级见 `bridge.default_db_path()`。
- **双端协调**：env/db/存储键改名合入后另一端重跑即触发同一迁移，幂等覆盖。
- **验收**：迁移测试钉死（首次迁移 / 已迁移跳过 / 显式 `BUTLER_DB` 不迁移 /
  kabao 旧库源优先于 marina 源 / CWD 同名文件不迁移）。
