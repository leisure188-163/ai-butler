# A1-01 · 产品定位与能力全景

> 状态：v1.1（2026-11-12，命名与语言按 A1-03 收编）
> 决策：**不在前代项目 auto-signin-kit 上重构，全新实现**（见 `../legacy/A0-01-旧系统知识资产.md`），
> 旧项目只是**协议字典 + 行为验收基准**，**严禁代码搬运**——
> 新系统存在的理由就是旧架构已暴露弊端，全量移植等于重蹈覆辙。

## 1. 一句话定位

> **AI 智能助手管家**：一个本地优先的管家——把你在各家 AI 助手里的账户、凭据、
> 权益、用量统一管理，自动领取、计量、调度，并做迁移。

- 英文 tagline：*One wallet for all your AI accounts.*
- 中文 tagline：**你所有 AI 助手的账户权益，交给一个管家——领取、计量、调度，一件不落。**
- 仓库：Gitee `hiclaw_520/ai-butler`（2026-11-14 由 `ai-kabao` 更名）
- 词表与命名标准：[A1-03 命名与语言标准](A1-03-命名与语言标准.md)（唯一事实来源）

## 2. 用户与核心任务（JTBD）

| 场景 | 用户想说的话 | 产品给什么 |
|---|---|---|

## 3. 能力全景（L0~L7）

### L0 底座（M0 必建，一切能力的地基）
| 能力 | 说明 |
|---|---|
| 凭据保险库 Vault | 凭据统一加密托管：存取、有效期监控、到期提醒、轮换记录；OS Keychain 为主 |
| 账户健康中心 | 登录态探测、令牌过期预警、封号风险信号、账户分级（健康/临期/失效） |
| 事件总线 + 通知中心 | 统一事件模型（RunFinished/CredentialExpired/QuotaLow/ProtocolChanged…），输出系统通知/Webhook/飞书/邮件 |
| 审计日志 | 谁、何时、用了哪个凭据、做了什么写操作；反代上线前必须就位 |

### L1 权益（对齐 auto-signin-kit 现状）
- 领取 / 补签 / 成长中心（WorkBuddy 全链路：旅行、任务、补登、兑换、盲盒）
- 幂等领取、领取窗口语义（credits_refresh_time）、脱敏、时间预算——全部保留
- **活动时间表**：见 §4

### L2 用量（R2）
- 采集源：客户端本地日志/库、API 用量接口、反代自身计量
- 存储：SQLite 时序表按天分区（量大换 DuckDB）
- **流量（耗尽预测）**：不只"用了多少"，而是"每个账户还剩多少、几天后耗尽"——反代路由的输入
- 采集器与展示解耦：采集失败不影响领取

### L3 网关（R4）
- 组件：Provider Adapter → Credential Pool → Router（余额/延迟/故障转移）→ Limiter → Meter → Audit
- 协议面：先 OpenAI-compatible 与 Anthropic-compatible 两个标准面
- **独立进程**：主控管"配置与观测"，网关只管"转发与计数"，IPC/HTTP 通信；将来换 Go/Rust 只换这一个进程
- 定位：个人多账户聚合（仅本机、仅本人账户），不宣传不商用

### L4 会话（R5，产品上必须克制）
- 三级能力如实标注：`local`（本地会话文件迁移）/ `inject`（摘要注入新会话）/ `server`（官方共享能力）
- 只承诺「可迁移 + 可回退」，不承诺「无缝」

### L5 数据资产
会话资产库（索引/搜索/导出）、跨工具迁移、Prompt 资产库、配置即代码（工作区导出/导入）

### L6 智能优化
成本顾问（基于用量给套餐建议）、套餐对比、路由策略（按模型/成本/延迟/场景）

### L7 生态输出
- **MCP Server**：把能力暴露成 MCP 工具（查额度/触发领取/切账户）——用户全是 AI 工具重度用户，这是最自然的分发渠道
- 开放 API + Webhook、连接器市场（**第三方连接器沙箱执行**）、多设备端到端加密同步（可选）
- 协议守护：上游改协议 → 自动探测失败 → 通知 + 社区补丁通道；auto-signin-kit 的 NOTE-01~04 沉淀为版本化连接器协议文档

## 4. 活动时间表（专项设计）

> 借鉴：数字生命卡兹克「Token 羊毛聚合站」（aihot.news/free-tokens，2026-11-09）。

1. **三级漏斗采集**：关键词宽筛（每小时）→ LLM 二次判断（是否真羊毛，标注排除原因）→ Agent 核实（仅对可信来源唤醒：官方账户/多源一致/直链官方页）——控制信源噪音与核实成本
2. **「值得领」负面清单**：排除返利/邀请链、API 中转站、二手积分、共享账户、接码多开、需先充值——与免责边界对齐，只聚合厂商公开运营活动
3. **生命周期**：`active / ending / expired` 三态；上架记录厂商原话，每日对照两次，临期提醒，过期自动下架
4. **首页指标**：当日可领金额、本月已领金额（进「首页」页）
5. **游戏化**：收集册（领过的活动变成卡片，普通/稀有/绝版）、"今天已领"墨印
6. **分组维度**：按领取频率（每日/每周/新人礼包/限免），不按厂商
7. **信源可插拔**：本地官方渠道直查 + 订阅外部聚合源（AIHOT 引擎已开源，做成可选 Connector）；社区提报走连接器市场同一套审核流水线

## 5. 里程碑

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| 设计 | 产品定位/架构/详细设计/前代项目知识资产 | ✅ 完成 |

| M1 | 权益 | **全新实现**首批 4 个 Connector（trae → qoder → doubao → workbuddy，由简到繁）；每个不加特殊分支接入新模型 = 底座正确性硬标准；旧系统仅作行为验收对照 ✅ 完成（四连接器真机验收，PROTOCOL §5 勾账） |
| R1 | 命名与语言 | butler 统一命名 + 词表 v2 + 侧边栏（A1-03）✅ 完成 |

## 6. 合规边界

- L1/L2（自己账户、自己用量）风险低；L3/L4 触碰 ToS，风险高
- 反代定位「个人多账户聚合」，文档显式声明封号风险；不做共享账户/转售
- 会话跨账户迁移可能触发风控，产品文案如实标注
