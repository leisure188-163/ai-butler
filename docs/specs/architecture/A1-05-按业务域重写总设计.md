# A1-05 · 按业务域重写总设计

> 状态：**生效 v1.0（2026-11-14）**　决策：[ADR-002](../../adr/ADR-002-core按业务域分包.md)
> 本文件是 core/engine 按业务域重写的**唯一总设计**：域图、包结构、多账号模型、
> 数据迁移、阶段计划与验收都在这里。各业务域的实体/端口/用例细则见 A2-04..A2-08。

## 1. 域图（五个业务域 + shared 内核）

| 业务域 | 职责 | 对应用户词（词表 v2） | 现有代码来源 |
|---|---|---|---|
| `shared` | 跨域公共内核：Event 六型、Status 七字面量与分类谓词、errors、id/time 基础设施 | — | event.py、results.py、errors.py |
| `accounts` | Provider、Account 集合、凭据/权益/会话、注册与导入 | 账户 / 导入 | account.py、vault.py、register_account |
| `execution` | Action、Run、幂等键、时间预算、执行动作 | 领取 | action.py、run.py、execute_action |
| `usage` | UsageSample、额度三型语义谓词、采集 | 流量 / 用量 | usage.py、collect_usage |
| `health` | 健康分级、风险规则、凭据到期扫描 | 体检 | health.py、health_scan |
| `scheduling` | Trigger 三型、调度窗口、待办队列 | 时间表 | schedule.py、list_pending |

判定规则：**新增能力先问属于哪个域**；说不清 → 先在 ADR 里立项为新域，不许
塞进现有域的杂项文件（一域一册，conventions/4 同源）。

## 2. 包结构与依赖规则

```
packages/core/src/butler_core/
├── shared/          events.py / results.py / errors.py / ids.py
├── accounts/        domain.py  ports.py  usecases/register_account.py
├── execution/       domain.py  ports.py  usecases/execute_action.py
├── usage/           domain.py  ports.py  usecases/collect_usage.py
├── health/          domain.py  ports.py  usecases/health_scan.py
├── scheduling/      domain.py  ports.py  usecases/list_pending.py
└── bootstrap.py     纯装配根（组装各域 + 注入 engine 适配器）

packages/engine/src/butler_engine/    # 对齐同一域图
├── db/              sqlite WAL / 迁移 / 分区
├── accounts/ events/ usage/ health/ scheduling/ vault/ audit/ notify/
└── bridge.py        装配出站适配器
```

每域三件套（固定形态，不许增删层级）：

- `domain.py`：实体 + 不变量 + 域内谓词（纯数据与规则，零 IO）
- `ports.py`：**该域**的端口 Protocol（端口随域走，废止单一全库 ports.py）
- `usecases/`：该域用例（一用例一文件，沿 conventions/4 §2.3）

依赖恒等式（verify 机检目标）：

```
域 domain.py   → 只 import shared
域 ports.py    → 只 import 本域 domain.py + shared
域 usecases    → 可 import 本域全量 + 其他域的 ports.py（跨域编排只经端口）
engine 各子模块 → 对应 core 域的 ports.py，禁止反向
```

## 3. 多账号模型（ADR-003 落地）

1. **Account 是集合**：一个 Provider（Connector）下 N 个 Account 并行，
   身份 = `(provider, account_key)`；`account_key` 缺省 `"main"`，
   存量单账号数据迁移时自动落位，零信息丢失。
2. **target 编址** = 应用 + 账号；MCP/CLI 兼容层保留裸应用 id = 首账号
   （ADR-003 §2，避免既有调用断裂）。
3. **幂等键** = `(kind, account_id, 窗口)`；签到/领取/采集全部按账号粒度，
   `is_quota_low` 等谓词输入随账号隔离。
4. **凭据/权益/会话/用量全部挂在 Account 下**，vault 内凭据绑定 account，
   不再按应用共享（ADR-003 §5）。
5. **契约再生成**：accounts/runs 端点键位加账号维度，import 返回多账号形状；
   按 P6 统一走红线 4（`gen:sdk` + openapi.sha256 同步）。

## 4. 历史包袱收口（不带入新代码）

| 包袱 | 处置 |
|---|---|
| `marina.vault` 读穿（Windows credman / macOS keychain） | 一次性迁移脚本：旧前缀凭据读取后写入新 `butler` 键；迁移幂等、旧文件保留不删、写审计（承袭 A1-03 §7 机制）；新代码零 legacy 分支 |
| `results.py` legacy 方言自映射 | 新 `shared/results.py` 只保留 `from_engine` 单一翻译入口 + **纯数据字典**（ADR-004 方言注册表的 oracle 对齐，测试钉死七字面量）；不新增任何运行时兼容分支 |
| `ProvisionRequest` ports 类型历史透传 | 重写后 engine 直接 import 本域 ports，透传删除 |
| `kabao.db` / `kabao.settings.v1` 旧标识迁移 | 双腿迁移（db + localStorage），机制不变，随新 engine 重实现（A1-03 §7） |

## 5. 阶段计划（每阶段 = 测试全绿 + 门禁九项全绿）

| 阶段 | 内容 | 交付物 |
|---|---|---|

P5 可与 P4 并行启动；P6 收口。

## 6. 验收标准（Definition of Done）

1. `python scripts/verify_project.py --project . --test` 九项全绿
2. 全量测试绿：core 用例单测 + engine 迁移测试 + 连接器契约测试
3. `packages/sdk` 契约再生成且 web 编译（vue-tsc）通过，DTO 派生自新契约
4. 全库 `grep kabao` 仅剩历史文档（早期 ADR 与 A0-01 保留原词）与迁移兼容
   代码/文档中的旧源路径字面量（A1-03 §7 迁移口径；docs/superpowers/ 历史任务书
   已于 2026-11-14 按用户清理要求删除）
5. AGENTS.md 路由无悬空引用；STATUS.md 记录每阶段完成态
6. 协议七字面量、连接器业务码字典零变化（oracle 对齐测试钉死）
