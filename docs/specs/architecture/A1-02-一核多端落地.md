## 1. 为什么一核多端成立

Butler 的四个能力域对运行形态要求相反，但**共享同一个领域核心**（账户/凭据/权益/用量）：

| 能力 | 形态 | 落点 |
|---|---|---|
| L1 签到 / L2 采集 | 批处理（跑完即退） | server 调度 + CLI 直调 core |
| 主控/管理台 | 常驻本地服务 | apps/server (FastAPI) |
| LLM 助手接入 | stdio 宿主（随客户端启停） | apps/mcp（MCP 薄壳，走 server 契约 API，ADR-009） |
| L3 反代 | 常驻 + 高并发 | **独立进程** apps/gateway（R4 引入；进程边界/通信/栈裁决见 ADR-012） |
| 桌面/托盘 | 壳 | apps/desktop (Electron + sidecar) |
| CLI/排障 | 薄壳 | apps/cli (Typer) |

**核心只有一份**：`packages/core`（纯 Python、零框架依赖），端与进程都是壳。
CLI 与 server 进程内直调 core；desktop/web 走 OpenAPI 契约 SDK。

## 2. 分层与依赖方向（恒向内）

```
apps/cli | apps/web | apps/desktop | apps/uniapp      ← 壳，禁止业务规则
        ↓ OpenAPI 契约（packages/sdk 自动生成 TS）
apps/server（编排/路由/调度触发）→ packages/core
                                          ↓
        packages/core（领域 + 用例，唯一业务规则出处）
                                          ↓
        packages/engine/（出站适配器：HTTP / 凭据解锁 / CDP / SQLite / 调度器）
```

从 auto-signin-kit 吸取的教训直接落进门禁：
- core 零框架 import（verify 检查项 AST 级把关）
- 端零映射：结果语义枚举只在 core，`grep` 各端不得出现 `PASS_RESULTS = [...]` 类映射表
- 适配器不做语义决策：只做形状转换 + 如实申报 capabilities + 回填结构化结果

## 3. 领域模型（按业务域分包，细则见 A1-05 §1/§3 与 A2-01）

```
Workspace（本机工作区）
 └─ Provider（AI 产品：Trae / Qoder / 豆包 / …）
     └─ Account（聚合根；**集合**——一 Provider 挂 N 个账户，ADR-003 落地）
         ├─ identity: (provider, account_key)，缺省 account_key="default"
         ├─ Credential（可轮换、可过期；按账户隔离；状态由健康中心维护）
         ├─ Entitlement（签到状态、积分余额、连签）
         ├─ UsageSample（token 输入/输出、时间、模型、来源）
         └─ Session（本地会话集合；可导出/导入/映射）
横切：Capability（checkin / usage.read / chat.proxy / session.move…）
      Action/Run（幂等键 = (kind, account_id, 窗口) + 结果 + 证据）
      Trigger（cron/事件/阈值）  Event
```

core 内部按**五个业务域 + shared 内核**分包（shared / accounts / execution /
usage / health / scheduling，每域 `domain.py + ports.py + usecases/`），
域图、依赖恒等式与包结构见 [A1-05 §1/§2](A1-05-按业务域重写总设计.md)；
各域实体/端口/用例细则见 A2-04..A2-08。

**结果词汇单源**（core-first 原则）：`shared/results.py` 七字面量
（CLAIMED / ALREADY / FAILED / NO_AUTH / PENDING / EXPIRED / SKIPPED），
每个字面量配分类谓词（is_pass / is_fail / kind），端上渲染只消费谓词。

## 4. Connector 机制（扩展性的核心）

每个 AI 产品 = 一个 Connector 包，声明能力矩阵。三级扩展对应三种接入成本：

| 方式 | 适用 | 成本 |
|---|---|---|
| 声明式 YAML | 纯 HTTP 接口（Trae 签到） | 极低，用户/社区可写 |
| Python Connector | 需解密/本地客户端/CDP（Qoder、豆包、WorkBuddy） | 中，官方维护 |
| 独立进程 Adapter | 高并发反代等 | 高，仅官方 |

```yaml
id: trae_cn
display: Trae CN
capabilities:
  provision.run: { declarative: {...} }      # 只在 L1 用声明式
  usage.read:        { adapter: python }
  sessions.move:     { level: local }          # local / inject / server
credential: { kinds: [ss_aes], unlock: local-client }
```

红线：**L1 允许声明式；L3 网关禁止声明式**（需要流式转发与计量，不是状态机）。
第三方连接器在沙箱执行，凭据最小授权（L7 市场的前置条件）。

## 5. 目录规划（ADR-002 换代后）

```
packages/core/        butler_core：shared/ + 五业务域分包 + bootstrap
                      （域图与三件套形态 → A1-05 §2）
packages/engine/      butler_engine：db/ + 同域图子模块 + bridge（出站适配器）
packages/connectors/  trae_cn/ qoder_cn/ doubao_cn/ workbuddy_cn/ chatgpt_web/
                      claude_web/（一产品一 Connector 包，A2-02）
packages/sdk/         openapi.json → schema.d.ts（契约新鲜度由 verify 把关）
apps/server/          主控 API + 调度触发 + 事件总线
                      路由按 accounts/apps/runs/usage 四域分模块（conventions/4），
                      api.py 纯聚合器
apps/cli/             内部执行器 + 排障工具（降级为非主入口）
apps/mcp/             MCP stdio 薄壳（查额度/查用量/触发领取；零 core/engine
                      import，HTTP 走 server 契约 API，ADR-009）
apps/web/             管理台（Vue3 + Vite，IA 见 A1-03 §4 / A3-01）
apps/desktop/         Electron 壳（托盘 + sidecar）
apps/gateway/         反代独立进程（R4）
```

web 端 DTO 一律派生自 `packages/sdk` 契约（红线 4）。

## 6. 数据层

- SQLite（WAL）单库起步；Repository 接口隔离，禁止 SQL 散进用例
- 用量三表（快照/汇总/额度流水）随业务表同库；时序独立表（`usage_samples`）
  **单独设计、按天分区**仍是 R 系列方向（量级未到阈值），落地走 user_version 显式迁移
- 台账写入失败不影响业务主流程（沿用 auto-signin-kit ingest 语义）

## 7. 门禁与工程纪律

1. `python scripts/verify_project.py --project . --test` —— 结构/纯净性/依赖方向/六边形桥/token 闭合/契约新鲜度/空包/测试，八项结构检查 + 测试 = 九项全绿
2. uv + pytest（承袭 auto-signin-kit 工具链；ruff 尚未配置，引入时先补本行）
3. 每次架构裁决写 `docs/adr/`（沿用旧仓库 ADR 习惯）
4. 设计 token 唯一来源 `apps/web/src/styles/tokens.css`，决策记录在 `docs/DESIGN-DECISIONS.md`

## 8. 关键选型（承袭 skill 默认，差异标注）

| 项 | 选择 | 备注 |
|---|---|---|
| 桌面壳 | **Electron**（skill 默认 pywebview，本项目改） | 需要托盘常驻 + 已有 Electron 壳经验；sidecar 模式复用 |
| 包管理 / API / CLI / 前端 | uv / FastAPI / Typer / Vue3+Vite+TS | 与 skill 默认一致，团队已熟 |
| DB | SQLite（单机产品正确选择） | 不上 PG/Redis/MQ——模块化单体，过早分布式化是负债 |
| 鉴权 | 本地服务默认不设 JWT（127.0.0.1 单用户）；多设备同步引入时再加 | 差异点 |
