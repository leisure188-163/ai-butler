## 1. 左侧边栏导航（四页，矩阵即首页）

```
卡包 Kabao    ← 文字标「卡包 Kabao」+ 品类句「AI 账号管家」（金箔符退役）
账号    ← 默认页：应用×账号矩阵 + 常驻待办栏（产品本体，#/accounts）
用量    ← 套餐余额/流水/耗尽预测（#/usage）
记录    ← 操作台账（#/log）
设置    ← 页内三节：通用 / 提醒规则 / 关于（#/settings）
```

- 四项平铺（无分组标签）；「账号」项带角标 = 待处理 + 非正常卡 + 即将到期凭据
  （条目数，不去重）
- 页面状态 = hash 直链：可直链、可后退；旧直链兼容映射（命中即 replaceState
  重写为规范 hash）：`#/home`、`#/wallet`、`#/card`、`#/alerts` → `#/accounts`，
  `#/radar` → `#/usage`
- 概念翻译（用户永远不看到的词）：domain→应用、account→账号、
  connector→（实现细节，只在"关于/诊断"出现）、credits_refresh_time→"积分刷新时间"

## 2. 页面规格

### 账号（AccountsPage，矩阵主页 = 产品本体）
- **页头一句话结论**（聚合只数数，语义词来自 signal）：
  "X 个账号状态正常" / "N 项待处理" / "还没有接入任何应用"
- **批量动作**：一键导入（未泊位应用数）/ 一键领取（已泊位且申报
  `provision.run` 的应用数——计数与行为一致，不虚报）
- **矩阵表**（行 = 账号，天然兼容一应用多卡——多账号即多行，见 ADR-010）：

  | 列 | 内容 |
  |---|---|
  | 选择 | 批量勾选；表头全选 = 当前筛选结果全选 |
  | 应用 | 小徽（身份色点 + 应用名） |
  | 账号 | account_id（mono） |
  | 状态 | signal 结果徽（.tag，端零映射） |
  | 今日动作 | signal 判定：有 ok=「✓ 已完成」/ 有非 quiet 非 ok=「✗ 未完成」+原因 / 全 quiet=「进行中」/ 无=「未做」（本地自然日） |
  | 额度 | radar 最紧活跃包一行「余/总 单位」+ 低额标记；无数据如实「—」 |
  | 凭据 | 最早到期 + 临期标记（notice） |
  | 最近操作 | 最近一条 run 时间 |
  | 动作 | 领取/体检（能力申报驱动）/详情 |

- **筛选**：按应用、按状态（全部/需处理/正常）——只影响表格行与全选范围，
  不影响批量计数
- **批量条**：勾选 >0 时出现「已选 n · 批量领取（m）」——逐个顺序执行，
  结果如实逐条转述；**批量体检不做**（每日巡检 R3-2 已覆盖，YAGNI）
- **详情**：点行在行下展开体检明细（凭据清单/证据/repair_hint/能力驱动按钮）
- **未导入应用** = 虚线邀请行「＋ 导入 {应用名}」；完全空态给行动指引
- **常驻待办栏（TodoRail）**：三节——**已自动完成**（今日巡检一句话，
  系统只汇报真做过的动作）/ **需要你处理**（pending + 人话原因 + 证据折叠 +
  能力驱动领取按钮）/ **即将到期**（notice 凭据 + 有效期）；
  全部清静时明说「没有需要你操心的事」
- 响应式：≤900px 待办栏下沉到矩阵下方；额度/凭据/最近操作列隐藏

### 用量（UsagePage，原「额度雷达」改名）
- **每账号一块**：小徽头行 + provider/采集时间；活跃包（余额大数字 +
  进度条 + 已用/周期/状态 + 耗尽预测或「采集中——再采一帧即出耗尽预测」）；
  已耗尽历史包折叠；用量汇总原话折叠（连接器原话直渲染）；最近流水
- 数据由壳下发（radar 拉取与轮询统一）；「立即采集」结果如实分列
- forecast 缺失（不足两帧差分）如实显示「采集中」；quota_low 是 core 谓词
  出产的包名列表，只做布尔标记

### 记录（LogPage）
- **中性表**：表头浅灰底、数字 tabular、动作/账号 mono
- **结果 = 结果徽**（.tag，色相由 signal 决定），原文 status 如实展示
  （端零映射）；证据折叠在徽下方

### 设置（SettingsPage）
- **通用**：主题（跟随系统/卡纸与墨/墨夜/暖纸，默认跟随系统，
  `prefers-color-scheme` 实时跟随）+ 自动刷新开关 + 间隔；
  存 localStorage `kabao.settings.v1`，改即生效（App 壳轮询）
- **提醒规则**：只读展示 core 统一常量（到期预警窗 3 天 / 连续 3 次无授权判
  风险）并注明"暂不开放修改"（诚实边界，不假装可配）
- **关于**：产品名 + 品类句「Kabao（卡包）· AI 账号管家」/ 版本（取自
  server OpenAPI info，取不到显示 —）/ 数据位置 kabao.db / 仓库与接口文档外链

## 3. 组件结构（apps/web/src）

```
App.vue               壳：数据（含 radar 上收，独立容错）、轮询、动作、
                      hash 路由与旧直链兼容映射（页面状态唯一持有者）
components/SideNav    文字标品牌区 + 四项平铺导航 + 角标 + 刷新/更新时间
components/AppBadge   应用小徽（身份色单值点——全站唯一合法身份色载体）
components/TodoRail   常驻待办栏（三节聚合，语义沿用旧提醒页口径）
components/AccountDetail  行下展开的体检明细（凭据/证据/建议/能力驱动按钮）
pages/Accounts|Usage|Log|Settings
styles/tokens.css     主题单源（红线 6，v5 中性基底）；styles/ui.css 通用件
```

- 数据流：壳持有全部 fetch 与动作，页组件 props 入 / emit 出（不改 props）
- 服务端版本信息独立容错获取（dev 代理可能不转发 /openapi.json，失败静默）

## 4. 渲染纪律（端零映射的 UI 落点）

- 所有结果染色/图标/文案只由 core 出产的 `kind`/signal 谓词驱动；
  组件不认识具体 status 字面量
- 不把"已请求"渲染成"已领取"（PENDING 如实展示为"服务端判定暂不符合条件"）
- 排障信息（evidence/原始响应）一律折叠进"查看详情"
- 设计 token 唯一来源 `tokens.css`（红线 6）；**身份色只允许出现在
  AppBadge**（单值点，禁止大面积色块与渐变）
- 待办栏/结论只汇报系统真做过的动作（诚实纪律）
- 可访问性地板：焦点环全控件可见、正文对比 ≥4.5:1（五色 ink 档）、
  动效尊重 `prefers-reduced-motion`、空态必给行动指引
