## 1. 侧栏与导航

- **顶栏单行**：文字标「AI 智能助手管家」+ 拉丁标 Butler，
  不再维护第二行；≤900px 顶条同样显示主名。
- **六项平铺（页名词 v3，2026-11-18 用户裁决）**：**仪表盘（默认）/ 平台管理 / 账户管理 / 用量管理 / 运行日志 / 系统设置**；英文 hash 不变（dashboard/platforms/accounts/traffic/logs/settings），旧直链全部静默兼容。
- **提醒角标挂「仪表盘」项**（账户项不挂）：计数 = 待处理 + 非正常账户 +
  即将到期凭据，条目数不去重（口径与四页时代完全一致，零变化）。
- 概念翻译（domain→UI）：Provider → 平台；Account → 账户；Run → 日志行；
  Signal 五分类 → 结果徽 `.tag`；协议字面量不出 UI（词表 v2 两层词汇）。

## 2. 六页规格

### 仪表盘（DashboardPage，默认页）

各块全部复用现有件，**不开新端点**，聚合走前端 computed；
v6.3/v7 重排（2026-11-16，[DESIGN-DECISIONS](../../DESIGN-DECISIONS.md) D2 v7 / D3 v6.3）：

1. **今日一句话结论**（原账户页 headline 谓词逐字迁入、按词表 v2 换词）：
   正在打开仪表盘 / 暂时够不到服务（副行「确认 server 已启动后点刷新」）/
   {n} 项待处理 / **还没有平台名册**（副行指去平台页「未导入的平台」点「扫描本机」）/
   **还没有接入账户**（副行报「名册已就绪 N 家」，指去平台页点「扫描本机」重新接入）/
   {总数} 个账户，{n} 个需要留意 / {总数} 个账户状态正常。
   空库两档按名册是否已扫回分开说，扫描本机已合并「刷名册 + 接账户」
   （[ADR-031](../../adr/02-平台与同步/ADR-031-平台名单列归用户与同步只纳客户端.md) 决策 7）。
2. **上手自检卡（OnboardingCard）**：空库（0 账户）显示**三步引导**——
   ① 扫描本机（「未导入的平台」区块右上的「扫描本机」刷新名册并自动接入客户端账户，一般 5 家）
   ② 设好签到时间 ③ 跑第一次签到；
   有数据时改显自检清单（服务 / 平台接入 / 排班 / 账户健康），
   名册为空时「平台接入」行的文案与按钮切成「去同步」。
3. **速览四行 → KPI 卡行（v7 图标片 + 占比环）**：账户健康分布
   （ok / 需留意 / 异常，按 signal 五分类 `.tag`；36px 占比环只画真实比值）·
   今日自动动作（本地自然日 runs：X 完成 · Y 未完成；完成占比环）·
   流量速览（内嵌水位条，最近采集于 {时间}，最低额度 {account_id}；
   空 →「尚未采集」）· 下次班次（主数字 HH:MM + 分钟倒计时；
   无排班 →「未排班」）。图标片色只表功能分类不表状态（D2 v7）。
4. **双栏区（v6.3）**：左 = **TodoRail 三节**（已自动完成 / 需要你处理 /
   即将到期，含证据折叠与能力驱动的领取按钮；账户页不再挂待办栏）；
   右 = `QuickPanel`（**快捷入口**四片纯导航：接入平台/去领取/去采集/看日志；
   **班次时刻**卡：`schedule_times` 并集升序 + 未到/已过标注，
   无排班如实留白）。
   - **待办修复入口（ADR-015/016）**：pending 项带 `repair_action_id` 时显示
     「重新登录 / 重新扫描」；点开是行内两步引导——「1. 在 {target} 客户端退出
     并重新登录；2. 点『我已登录，立即重试』（会先重新读取本机凭据）」。重试顺序
     固定为 `POST /apps/{target}/import` → `POST /runs`（带 `account_id`），
     结果按真实 status 回显，不在端上判定成败；导入未发现该账户时如实提示。
   - **撤销可见（ADR-015）**：账户详情的凭据行在 `revoked=true` 时显示
     「本地副本已撤销，等待重新停靠」；已撤销凭据不参与「最早到期」计算。
5. **近 30 天签到日历条带**（v6.2 ①，通栏收尾）：账户行 × 天列点阵，
   数据 = ledger 真实 run，不编造。

### 平台管理（PlatformsPage）

- 页头「平台」+ 副题「本机接入的各家 AI 助手与其能力、时间表。」+ 右侧只保留「＋ 自定义平台」；
  **页头「接入全部」删除**（2026-11-19 用户裁决：与「扫描本机」重复）。行内「接入」/「刷新」按语义分列，
  不再有「同步全部」；扫描动作只归「未导入的平台」区块，命名「扫描本机」。
- **十列表**（2026-11-18 裁决）：平台编码 | 平台名称 | 平台类型 | 版本号 | 平台状态 | 能力 | 调度执行时间 | 账户数 | 账户状态 | 操作；
  类型与版本各自独立成列（空值「—」）；「平台状态」= 启用/已停用徽（区别于「账户状态」的 signal 汇总）；末列表头词为「操作」。
- **平台信息编辑**（2026-11-18）：详情折叠「平台信息」小节展示显示名/状态/**凭据类型**/调度时间，点「修改」打开**弹层编辑态**（2026-11-18 起新增与修改统一走 `ModalShell`：遮罩点击/Esc 可关，保存中禁关）
  （显示名 ≤40 字 + 「恢复默认名」、启用勾选、HH:MM 时间列表可增删上限 8、保存/取消）；保存即刻生效。
  调度被改过的平台在编辑态多一个「**恢复平台默认调度**」（`times=null`，跟随连接器 manifest；
  与「清空时间 = 该平台不排班」是两种语义）。操作列另有「停用/启用」一键切换。
  平台编码、类型、版本、能力、凭据类型不可编辑（连接器探测所得，界面明示）。
- **操作列收成下拉**（2026-11-18）：直连按钮**最多 2 个**（接入/刷新 + 立即领取），其余（去账户 / 停用·启用 / 详情 / 删除）
  统一进「更多 ▾」下拉——否则一行 6 个按钮把列宽撑爆。菜单走 `RowActionMenu`（Teleport + fixed 定位，
  按按钮 `getBoundingClientRect` 右对齐、下方空间不足时上弹；点外部 / Esc / 滚动即关），表格 `min-width` 随之下调至 1030px。
- **交互收敛**（2026-11-18 裁决）：① 点击表格行不再展开详情（防误操作），仅「详情/收起」按钮控制；
  ② 末列表头词为「操作」；③ 详情内三段（能力清单 / 调度执行时间 / 账户）改为折叠小节，默认全收起、
  点标题展开、一次只开一节；④ 页脚旧「尚未接入的平台（n）」区块删除（2026-11-19 用户裁决）——
  它与「未导入的平台」重复，且在名册平台无账户时制造第二套「接入」入口。
- **未导入的平台（N）**（2026-11-19，[ADR-031](../../adr/02-平台与同步/ADR-031-平台名单列归用户与同步只纳客户端.md)）：同步只自动纳本机客户端 + 用户自建平台，
  内置网页版不自动进名册，收在「未导入的平台」白卡（默认收起；**标题栏整行可点**——点标题 / 计数 / 右侧箭头
  任一处即展开或收起，不要求对准「展开」文字；**区块常显，即使清单为 0**，
  因为右上「扫描本机」是名册被清空后的唯一找回入口）——区块右上动作「**扫描本机**」（刷新图标 + 文字，
  扫描中显示「扫描中…」），语义 = **扫本机客户端 + 刷新平台名册 + 自动接入已登录的客户端账户**
  （网页版仍留在这里手动导入）；**必须是全量重扫**（2026-11-20 修复）：`import-all?include_docked=true`
  对全部活跃本机客户端平台逐家 dock，已有账户的平台也重扫——账户已有 ≠ 客户端没有新账号，
  豆包这类多账号客户端靠这一步才能把漏接的第二个账号补进册（dock/注册按 (platform, account_code)
  幂等回放，只补新增、不动既有账户）；结果消息按事实分列「平台名册：n 个 · 已扫到 n 个账户 · 未发现登录态：…」；
  **自适应卡片网格**（`auto-fill minmax(168px, 1fr)`，宽屏一行 4~5 枚、窄屏 2 枚、gap 8px），
  每枚卡片只有**官方图标 + display 名称**，整卡即导入按钮（hover 主色边框 + 浅底 + ＋ 转主色，
  title/aria =「导入 xx」）；编码、类型徽、账户注释一律不显示（2026-11-19 四次改版：
  用户否掉整宽长条行「难看、占空间」，要求卡片化)，点击卡片 = 纳册 + 立即接入。
  删除账户不会让平台退回这里：平台只在名册行被删除（「删除平台」）后才进入未导入清单。
- **删除平台**（2026-11-19）：操作列「更多」菜单所有平台都有删除项，界面词统一为「删除平台」（danger 色；内部裁决术语「移出名册」），
  点击先出 `ModalShell` 确认（说明「账户、凭据与历史台账都保留，之后可在『未导入的平台』重新导入」），
  确认后 `DELETE /platforms/{code}`，平台退回未导入清单；自定义平台仍为「删除」（连连接器目录一起删），走 `DELETE /platforms/custom/{code}`。
- **检索条**（2026-11-18）：表格上方一条——关键字（平台编码 / 名称实时过滤）+ 全部状态/仅启用/仅停用
  - 全部类型/网页版/客户端 + 排序（平台编码 / 名称 / 账户数），有筛选时出现「清除筛选」。
  **平台总数不在检索条重复展示**（2026-11-18 裁决：页头副题的「（共 n 家）」与检索条的「n / 总数 个平台」一并删除，
  数量只在页脚分页处出现一次）。
  换条件回第一页，零匹配显示「没有匹配的平台——换个关键字，或点「清除筛选」」。纯前端筛选，零新端点。
- **行内「立即领取」**（2026-11-18）：已导入且申报 `provision.run` 的平台直接一键领取
  （复用账户域发起动作，target = 平台编码），职责等同账户页领取，不必跳页。
- **自定义平台（2026-11-18）**：页头「＋ 自定义平台」打开**弹出界面**（`ModalShell` 遮罩 + 居中卡片，
不往页面里塞内联表单；不是 YAML 编辑器——新手看不懂五段式），
  只问 4 件人话的事：平台编码/名称/登录域名/登录态 cookie 名 + 状态查询（GET/POST + URL + 请求体 +
  判定方式「业务码 code_path=expect_ok」或「布尔 checked_in_path」）+ 领取请求 + 调度时间（可留空）。
  保存 → server 校验后渲染成声明式连接器并热加载；到名册点「接入」才抓登录态、登记账户。
  名册里自定义平台的编码列带「自定义」徽，操作列多「删除」（`window.confirm` 二次确认；
  删后名册自动落 deprecated、历史台账保留）。编码被内置占用 = 409，声明不完整 = 422（detail 直显）。
  弹层壳纪律（`WebModalShell`：`ModalShell.vue`）：只做遮罩/卡片/标题/关闭/Esc/滚动锁，业务字段由调用方 slot 提供；
  遮罩色走 token `--color-scrim`（三主题各自定义），窄屏（≤640px）卡片转全屏、底部按钮竖排。
  表单版式（2026-11-18 二次改版）：四段分组——基本信息 / 状态查询 / 领取请求 / 调度，
  「基本信息」组内两列等宽，其余组内单列纵排（原版把两组接口横排成两列，窄卡片里列宽被内容拉扯、
  字段高度不一致、说明文字互相压字，是最直接的「乱」）。
  **表单类名必须带组件前缀**（本页 `cpf-`）：全局 `styles/ui.css` 有设置件 `.field`（flex + border-bottom）
  与列表行 `.row`，同名会把表单染成一条条带下划线的横排；需要复用的只有全局 `.input`/`.mono`/`.btn`。
- **分页**：每页 10 条，页脚「上一页 / 第 x / y 页 · 共 n 个平台 / 下一页」——n 为**筛选后**条数。
  能力文案 `provision.run→领取`、`health.check→体检`、`usage 类→用量`；
  时间表空 →「—」；账户数取契约 `account_ids`（空 →「未导入」虚线）；
  状态汇总按 signal 五分类小徽。
- 未接入平台虚线邀请行「＋ 导入 {平台名}」；点行展开能力清单 / 班次 /
  该平台账户（「去账户」跳账户页）。
- **新手可读性**（2026-11-18）：页头副题明示「平台来自内置连接器（共 n 家）——本机装好并登录
  对应客户端后即可接入」；「尚未接入的平台」每行带接入前提（客户端类=需装并登录客户端、
  网页类=需先在浏览器登录、未申报类型=需先登录对应客户端或浏览器），文案只按契约
  `platform_kind` 直译。未知 `platform_code` 点「接入」返回 **422 +
  「该平台没有连接器实现，无法接入：x」**（原为 KeyError 500）；批量接入对这类行逐家出账
  「没有连接器实现，已跳过」，不拖累其它平台。
- 空态「还没有平台——「扫描本机」把本机客户端接进来。」

## 3. 组件结构与路由

```
App.vue                装配壳（持有全部 fetch/动作/轮询，页 props 入 emit 出）
├── SideNav.vue        六项平铺 + 单行主名 + 角标在仪表盘
├── pages/DashboardPage.vue   headline + TodoRail + 速览四行
├── pages/AppsPage.vue        六列表册 + 导入入口
├── pages/AccountsPage.vue    页头 + 一键领取(n)（≤400 行）
│   └── components/MatrixTable.vue  9 列矩阵 + 筛选/批量/展开
├── pages/TrafficPage.vue     流量（原 UsagePage）
├── pages/LogPage.vue         日志（文件名不动）
├── pages/SettingsPage.vue    设置
└── components/               AppBadge / TodoRail / AccountDetail
```

- 数据流：`useShellData`（五端点并发）→ 壳 → 页 props；动作
  `useAccountActions` / `useUsageActions` 经壳 emit 下发；
  壳内新增纯派生 `claimable: Set<string>`（按 `capabilities.provision.run`），
  **composables 数据接口零新增、`api.ts` 零 diff**。

## 4. 渲染纪律（端零映射的 UI 落点）

- 所有结果染色/图标/文案只由 core 出产的 `kind`/signal 谓词驱动；
  组件不认识具体 status 字面量
- 不把"已请求"渲染成"已领取"（PENDING 如实展示为"服务端判定暂不符合条件"）
- 排障信息（evidence/原始响应）一律折叠进"查看详情"
- 设计 token 唯一来源 `tokens.css`（红线 6）；**身份色只允许出现在
  AppBadge**（单值点，禁止大面积色块与渐变）
- 待办栏/结论只汇报系统真做过的动作（诚实纪律）
- 可访问性地板：焦点环全控件可见、正文对比 ≥4.5:1（五色 ink 档）、
  动效尊重 `prefers-reduced-motion`、空态必给行动指引
- **操作反馈统一走顶部 Toast**（2026-11-19 用户裁决）：`useToast` 模块级单例
  + `AppToast` 组件，**页面顶部横向居中**弹出（`padding-top: 18px`，不吃点击）、
  3 秒自动消失、后一条覆盖前一条；只有 `ok` / `warn` 两态；各页不再自飘
  `.action-msg` 横幅，由 App 壳把各域 msg 逐源桥接到单例。**不放在页面正中**
  ——用户明确要求避开内容区。**配色**：整卡底色取主题弱色档
  `--color-ok-weak` / `--color-attention-weak`、文字取对应 ink 档，
  不再用「纯纸白底 + 3px 粗色左边线」（第二版白底深绿被用户指为
  与主题不呼应，已废弃）。
  例外：`loadError`（后端不可用）是**常驻系统态**提示，不进 Toast。
  注：`useToast()` 返回值需在组件里**解构到顶层绑定**——模板对对象属性上的
  ref 不解包（`toast.visible` 恒真、`:class` 会渲染成 `[object Object]`）

## 5. 多账号维度（ADR-003 落地后的展示面）
