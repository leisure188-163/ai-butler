## 1. 左侧边栏导航

```
卡包 Kabao          ← 品牌符（金箔芯片）+ 品名
总览
├─ 首页     ← 默认页，回答"今天有事要做吗"（hash #/home）
├─ 卡包     ← 应用接入 + 卡墙（产品本体，#/wallet）
└─ 记录     ← 领取记录表（#/log）
管理
├─ 提醒     ← 异常/到期/待处理聚合 + 角标计数（#/alerts）
└─ 设置                           （#/settings；页内三节：通用 / 提醒规则 / 关于）
```

- 菜单定名：`仪表盘`→**首页**（去工程词，圈外秒懂）；其余从词表 v1
- 提醒项带角标 = 待处理 + 非正常卡 + 即将到期凭据（条目数，不去重）
- 页面状态 = hash 直链：可直链、可后退（ui-ux-pro-max 深链规则）
- 概念翻译（用户永远不看到的词）：domain→应用、account→账号/卡、
  connector→（实现细节，只在"关于/诊断"出现）、credits_refresh_time→"积分刷新时间"

## 2. 页面规格（当前落地态）

### 首页（HomePage）
- **大字结论**（排印即横幅，不做盒子）："X 张卡状态正常" / "有 N 项待处理" /
  "卡包还是空的"——聚合只数数，语义词来自 signal 分类
- **卡扇**（唯一 orchestrated moment）：每账号一张真比例卡（1.586），
  轻微错落叠压 ±1.4°，载入一次错落揭示（260ms × 60ms stagger）；
  卡面 = 应用身份色 + 压印卡号 + 金箔芯片 + 状态脊（signal 色）+ 有效期；
  悬停抬起转正；扇尾常驻"＋导入应用"虚卡 → 卡包页
- **待处理**：行 + 发丝线——人话原因（repair_reason）+ 证据折叠 + 时间

### 卡包（WalletPage）
- **应用名册**：每行 = 应用 + 导入状态 + 时间表；动作 = 导入（扫描本机）/
  领取（主按钮，未导入禁用）；动作结果如实展示（CLAIMED/ALREADY/原因）
- **卡墙**：grid 真比例卡（同首页卡面规格）；**点卡展开体检明细面板**——
  凭据清单（kind/灯/有效期/level）、账号证据、repair_hint；再点收起
- 卡面身份色按应用 id 稳定散列分派（`--card-face-1..6`，白字 ≥6:1）

### 记录（LogPage）
- **打印感表**：表头浅灰底、数字 tabular、动作/账号 mono
- **结果 = 墨印章**：mono 小章（边框 1.5px currentColor，色相由 signal 决定），
  原文 status 如实展示（端零映射）；证据折叠在章下方

### 提醒（AlertsPage，已落地）
- 三节聚合：**待处理**（pending runs + 原因 + 证据）/**即将到期**
  （signal=notice 的凭据 + 有效期）/**需要留意**（signal≠ok 的卡 + 证据 + 建议）
- 每节给"去卡包"行动链接；全部清静时明说"没有需要你操心的事"（空态=邀请）

### 设置（SettingsPage，已落地）
- **通用**：主题（跟随系统/卡纸与墨/墨夜/暖纸，默认跟随系统，
  `prefers-color-scheme` 实时跟随，存 localStorage `kabao.settings.v1`）+
  自动刷新开关（switch, role=switch）+ 间隔（30 秒/1 分/2 分/5 分）；
  存 localStorage `kabao.settings.v1`，改即生效（App 壳轮询）
- **提醒规则**：只读展示 core 统一常量（到期预警窗 3 天 / 连续 3 次无授权判风险）
  并注明"暂不开放修改"（诚实边界，不假装可配）
- **关于**：产品名 + 品类句 / 版本（取自 server OpenAPI info，取不到显示 —）/
  数据位置 kabao.db（平台标准数据根）/ 仓库与接口文档外链

## 3. 组件结构（apps/web/src）

```
App.vue               壳：数据、轮询、动作、hash 路由（页面状态唯一持有者）
components/SideNav    品牌符 + 分组导航 + 提醒角标 + 刷新/更新时间
components/BizCard    真比例卡（首页卡扇与卡包卡墙共用；reveal/selected 形态）
pages/Home|Wallet|Log|Alerts|Settings
styles/tokens.css     主题单源（红线 6）；styles/ui.css 通用件（按钮/灯/行/章/设置件）
```

- 数据流：壳持有全部 fetch 与动作，页组件 props 入 / emit 出（不改 props）
- 服务端版本信息独立容错获取（dev 代理可能不转发 /openapi.json，失败静默）

## 4. 渲染纪律（端零映射的 UI 落点）

- 所有结果染色/图标/文案只由 core 出产的 `kind` 谓词驱动；组件不认识具体 status 字面量
- 不把"已请求"渲染成"已领取"（PENDING 如实展示为"服务端判定暂不符合条件"）
- 排障信息（evidence/原始响应）一律折叠进"查看详情"
- 设计 token 唯一来源 `tokens.css`（卡纸与墨主题，见 design-decisions D2）
- 可访问性地板（ui-ux-pro-max P1/P2）：焦点环全控件可见（卡面金 outline）、
  正文对比 ≥4.5:1（五色 ink 档）、动效尊重 `prefers-reduced-motion`、
  空态必给行动指引
